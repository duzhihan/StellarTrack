## 这一批做了什么

**1. 语义层体检七项清零**

原来的体检只查形式（版本、引号、引用、结构）。这一批补上语义层：条款之间是否自相矛盾、判据有没有执行载体、挂了引擎是不是真在用。清掉七处：
- 契约导语写“五条”实列六条
- 同一个守门号在不同文体下有三种判据
- 引擎声明义务没有落位的地方（现在写进状态盘与环节卡）
- 六个引擎登记了但工序里没有落点
- 非学术档的引擎基线只写了一句“按母版适配卡”
- 跨文件的重复条款没有同步机制（新建同步表）
- 音乐六层审与六维评分边界未声明，存在重复扣分

**2. 体检器从 6 项扩到 7 项**

新增“语义层三项”：守门判据族白名单、引擎零落点、共用条款同步表。做了反向自测——故意注入第五种判据写法与虚构引擎名，体检报 FAIL；还原后 7/7 PASS。

**3. 创作档补齐第七个子类：歌词**

新增歌词写作引擎（12 件，蒸馏自两部歌词教材），含十三辙韵表、十六种修辞、成稿七查、评审六层。

**4. 面向用户的文档重写**

README 从内部术语表改成用户叙事，配 5 张矢量说明图：流程与关卡、13 档位、三库分供、六维权重、规模自检。

**5. 两个工具链 bug**

- 引号守卫会把 HTML 属性里的引号转成全角，导致 GitHub 上封面图破图——已修，并给体检加了同样的豁免。
- 发布同步器把 GitHub 暂存目录也过了平台白名单，子 skill 的配图被剥掉——已修，暂存目录现在保留完整资产。
