# 运行时状态输出协议

> **目的**：让运行过程可视化——用户随时看到「当前在哪个环节、守门状态、进度、思考深度」。这是「做完 ≠ 做对」的可追溯凭证，也是星躔「像系统一样运行」的界面层。

**触发**：每次执行星躔，每个环节（O1/O2 → S → C1-C11 → E1-E3）开始时标记 `⏳`、结束时标记 `✓`（或 `✗` 回退）。**状态标识（5 态，v10.4.1 补挂起）**：`[✓]` 完成 · `[⏳]` 进行中 · `[⏸]` **挂起（interrupt：S1/S3/S5 强制确认点未裁决，产物=草稿版，C1 可并行准备）** · `[ ]` 待执行 · `[✗]` 回退。

**总进度视图**（每环节结束时同步更新，全程只维护一份）：

```
档位：学术档 ｜ 流程深度：标准 ｜ 状态：进行中
[✓]O1  [✓]O2  [✓]S  [✓]C1  [✓]C2  [✓]C3  [✓]C4  [✓]C5  [⏳]C6  [ ]C7  [ ]C8  [ ]C9  [ ]C10  [ ]C11  [ ]E1
```

**环节卡**（每环节结束输出一张，一句话即可；**含审计字段：思考深度 + 卡点结果 + 产物版本**）：

```
▌星躔·环节卡 ▌ C2 材料建档 [✓] ｜ 深度：🟡medium ｜ 卡点：缺口三项齐 ✓
守门④：材料充分性通过 → 放行
产出：文献账本 C2-xxx v1（含缺口卡）｜下一步：C3 综述·模型·引言
```

**铁律**：① 卡片必须真实反映当前状态，未运行不得标 ✓（呼应核心原则 4）；② 回退时在卡上标注回退原因 + 回退目标环节 + 深度变化；③ 跨会话交接时，进度视图随「O2 锚定卡 + P0 论证锚定卡 + P0-R 心月狐结果稿 + 写作状态摘要 + 进度卡」**五件套**必带（与运行协议第五节一致）；④ 深度升级/降级必须显式标注（审计日志并入进度卡，定案落地）。

**卡点内嵌提醒（拟人化 · v12.3.1）**：两个交互节点必须以第一人称给出可执行的下一步，不允许只挂状态不给路：
- **`[⏸]` 挂起时**：除状态标记外，附一句裁决引导——「我在这里需要你拍板：A……／B……／C……。你选哪个，我们就往哪走。」
- **守门打回 `[✗]` 时**：回退卡末尾加一句安抚+路径——「这道门我这轮没放行，原因是{X}。我们回到{目标环节}重来，已完成的产物都在，不会白做。回复『继续』我就重跑该工序。」
