# 回溯档工作流（结题报告 / 调研报告 / 执行情况报告）

> **档位定位**：回溯档 = 面对「管理部门 / 结题评审 / 资助方」这一话语共同体时，以可查证、数据准确、完整闭环为质量基准的表达方式。作者身份默认 = 项目负责人 / 课题主持人。
> **一句话**：回溯档写的是「立项承诺了什么、实际做到了什么、证据在哪里」——不是写新研究，是写「履约凭证 + 复盘结论」。
> **母版关系**：学术档是母版，回溯档关闭「论证创新」权重、开启「可查证·数据准确·完整」权重，骨架（S/C1-C6）不变。与学术档核心差异：回溯档以「立项指标」为标尺，逐条对账，不自由发挥。
> **加载时机**：O2 锚定卡档位 = 回溯档时，S/C1-C6 每道工序按本文件执行。
> **学术锚点**：结题报告的根本逻辑 = 「契约回溯」——以立项书约定的指标为基准，如实呈现完成度（对应科研经费与项目管理办法的结题审计要求）。

---

## S 论证锚定复核（回溯档）

复核四要点：
1. **结题要求**：主管部门对结题材料的具体规定（格式 / 必含章节 / 佐证类型）？
2. **指标对应**：立项书约定的核心指标有哪些（论文数 / 报告数 / 数据库 / 获奖）？须逐条对账
3. **材料清单**：原始数据、成果复印件、票据、伦理批件等是否齐备？
4. **时间节点**：结题截止？是否逾期？决定流程深度（逾期须补情况说明）

**档位特有复核项（S1 段）**：指标清单与材料底数确认 → 进入 C1。

---

## C1 选题（结题主题 · 定题四环节转义）

> 完整映射见学术档工作流 C1 节。回溯档 转义：
> 态势分析 → **结题要求（主管部门标准）**；选题推荐 → **结题主题候选**；定题评测三维 → **可查证性/数据可得/完整性**；标题打磨 → **结题报告题**。

1. 从 P0 论证锚定卡提取选题关键词
2. 按四环节收敛候选 → 定题评测三维均过 → 定稿选题
3. 输出选题卡 C1-xxx（定稿选题 + 四环节记录 + 备选题）

**守门③（选题定稿）**：三维均过 → 放行 C2。

## C2 材料建档（数据证据账本）

> 与学术档「证据账本」同构，但证据类型不同：回溯档的证据是**过程数据、产出佐证、经费票据、第三方证明**。

| 编号 | 事实 / 指标 | 证据来源 | 类型 | 可信度 | 对应立项指标 |
|---|---|---|---|---|---|
| D01 | 发表 CSSCI 论文 2 篇 | 期刊录用通知 + 原文 | 成果 | 高 | 指标①论文≥1 |
| D02 | 建成调研数据库 N=1200 | 数据库截图 + 说明 | 数据 | 高 | 指标②数据库 |
| D03 | 经费支出合计 X 万（合规） | 财务票据 + 决算表 | 票据 | 高 | 预算执行 |
| D04 | 未完成的指标：国际会议 1 场 | 情况说明 | 缺口 | — | 指标③（需解释） |

**材料缺口处理**：指标未达成 → 必须写情况说明（客观原因 + 补救），不得隐瞒；票据缺失 → 提示补开或写说明，不虚构。

**守门⑤**：每项立项指标均有对账记录（完成 / 部分完成 / 未完成+说明），无遗漏 → 放行。

## C3 结构设计（回溯档模板）

### 标准结题报告（六段）

```
标题：{项目名称} 结题报告（或执行情况报告）
一、项目概况（立项背景 + 约定指标摘要，1 段）
二、执行情况（按立项指标逐条对账：做了什么、怎么做的）
三、主要成果（论文/报告/数据库/获奖，附清单与佐证索引）
四、经费使用（决算表 + 合规说明，与预算对应）
五、存在问题与说明（未达标项客观说明 + 后续计划）
六、结论（总体完成度评价 + 价值简述）
附件：成果复印件 / 数据佐证 / 票据目录
```

**结构检查**：执行情况的每一条须对应立项指标编号（D0X↔指标①）；成果清单与 C1 账本一致；经费决算与预算科目对应。

**守门⑥**：指标全对账 + 成果附件索引一致 → 放行。

## C4 逐段写作（回溯档话术底线）

> 撰写顺序：先写**项目概况**（锁定标尺）→ 再写**执行情况**（逐条对账）→ 成果 / 经费 / 问题 / 结论。

**话术底线（写入时即带着）**：

- **数据先行**：每段以数据 / 成果开头（「本项目完成论文 2 篇、数据库 1 个」），不写「取得了一定成果」
- **对应立项口径**：成果表述与立项书用词一致（立项说「调研数据库」，结题不改成「数据平台」），便于评审对账
- **客观如实**：未达标项直写「因 XX 原因未完成，拟 XX 补救」，不淡化不掩盖；已完成项不夸大（「基本完成」而非「圆满完成」）
- **可查证表述**：成果附索引（「见附件 P3 录用通知」），不写无据断言；经费写「合计 X 万，详见决算表」
- **禁用 AI 腔**：禁用「综上所述 / 总体而言 / 在一定程度上」等模型套话；不写「本项目取得了丰硕成果」式虚评

**每节强制操作**：回顾该节对账功能 → 按话术底线撰写 → 标注对应指标编号 → 更新写作状态摘要。

**守门⑦**：数据有据 + 指标全对账 + 无夸大隐瞒 + AI 味禁用词 ≤3次/千字 → 放行。

## C5 对抗评审（回溯档三角色）

| 角色 | 审什么 | 输出 |
|---|---|---|
| 可查证评审 | 每项成果有无佐证？数据能否复核？ | 可查证问题清单 |
| 完整性评审 | 立项指标是否全对账？附件是否齐备？缺口是否说明？ | 完整问题清单 |
| 数据准确评审 | 成果数 / 经费数与账本、票据一致？口径统一？ | 数据问题清单 |

**C5b 回退**：可查证/数据问题 → C1（证据不足）；完整问题 → C2（结构遗漏）或 C3；口径问题 → C3。

**守门⑧**：三角色通过 → 放行至打磨。

---

## C6 打磨交付（回溯档）

1. **格式合规**：按主管部门结题模板（封面 / 签章页 / 附件顺序）
2. **附件核对**：成果复印件、数据库说明、票据目录逐条与 C1 账本对应
3. **签章完整**：单位审核意见 + 负责人签章 + 财务审核（如涉经费）
4. **生成发布就绪包**：标题备选 + 正文(合规格式) + 附件清单 + 报送清单（系统/纸质/截止）
5. DOCX 生成调用 `docx` Skill

**守门⑧**：格式合规 + 附件齐备 + 签章完整 → 终稿交付 → 进入 E 层。

## 附：回溯档高频文体速查

| 文体 | 结构重心 | 核心要求 |
|---|---|---|
| 课题结题报告 | 指标对账 + 成果 + 经费 | 逐条对应立项书 |
| 执行情况报告 | 进度 + 阶段性成果 | 如实反映进展 |
| 调研报告 | 数据 + 发现 + 建议 | 数据可查证、建议可操作 |
| 延期/终止说明 | 客观原因 + 补救计划 | 诚实、可核实 |
