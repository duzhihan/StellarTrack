# 研究报告模式 — 完整执行指南

> 本文档是论文工厂「研究报告模式」的详细执行手册
> 调用方：SKILL.md 中的新增第四模式
> 与其他模式的关系：课题申报模式是"前瞻"（我要做什么），研究报告模式是"回溯"（我做了什么、发现了什么）
> 执行方式：逐阶段推进，每阶段结束后必须经过质量闸门判定

---

## 质量保障策略

研究报告模式采用**结构合规 + 内容质量**的双层保障：

| 层级 | 闸门 | 检查内容 | 性质 |
|:--:|------|---------|------|
| L1 结构合规 | G1/G4 | 报告结构完整性、章节逻辑、格式正确、字数合规 | 致命——不通过不可交付 |
| L2 内容质量 | G2 | 五维评分≥35/50 + AI味禁用词≤3次/千字 | 影响评审评价 |

**与其他模式的差异**：
- 没有G3学术评审闸门——研究报告不是同行评议的学术论文，而是面向管理部门/项目委托方的成果汇报
- G2覆盖了内容质量（五维评分替代了学术评审中的多维效度审查）
- 核心重点在"成果的完整呈现"而非"论证的创新性"

## 阶段一：立项背景回顾

### 1.1 目标
明确本报告对应的项目/课题背景，建立"立项承诺→实际执行→成果产出"的完整叙事链。

### 1.2 入口条件判断

| 情况 | 处理方式 |
|------|---------|
| 殿主提供了原始申报书/立项书/合同 | 直接进入Step 1，提取关键承诺 |
| 殿主未提供原始文件 | 询问"请提供原始立项文件（申报书/合同/任务书），以便建立承诺-执行对照链"后等待 |
| 殿主口头描述项目背景 | 以殿主口头描述为准，辅助整理为结构化背景 |
| 新建调研报告（非结题） | 跳过立项对照，直接从研究问题开始 |

### 1.3 执行步骤

**Step 1：立项承诺提取**
从原始立项文件中提取以下要素：
- 项目名称、编号、来源
- 原定的研究目标（逐条列明）
- 原定的研究内容（逐条列明）
- 原定的预期成果（逐条列明：论文/报告/数据库/其他）
- 原定的研究周期与经费

**Step 2：实际执行对照**
逐条比对原定计划与实际执行：
- 哪些完成了？（标注完成情况）
- 哪些调整了？（说明调整原因）
- 哪些未完成？（说明客观原因）
- 哪些超出了原计划？（说明新增的附加价值）

**Step 3：报告定位确认**
判断报告的类型，确认结构模板：

| 报告类型 | 适用场景 | 结构侧重 |
|---------|---------|---------|
| **课题结题报告** | 国社科/教育部/省部级结题 | 成果对照 + 创新贡献 + 经费使用 |
| **项目研究报告** | 横向/纵向项目交付 | 研究过程 + 成果 + 建议 |
| **调研报告** | 专项调研任务 | 调研方法 + 发现 + 对策建议 |
| **年度进展报告** | 在研项目的年度汇报 | 年度工作 + 阶段性成果 + 下年计划 |
| **成果总结报告** | 成果报奖/推广宣传 | 成果亮点 + 影响 + 应用案例 |

**输出产物**：立项背景回顾报告 + 报告类型确认

**检查点写入**：`📁 论文输出/[项目名称]/01-立项背景回顾.md`

## 阶段二：研究过程梳理

### 2.1 → 闸门G1（结构完整性）

### 2.2 执行步骤

**Step 1：研究方法与过程记录**
按时间线或任务线梳理实际研究过程：
```
时间线梳理（推荐格式）：
202X.XX-202X.XX：文献调研阶段
  — 检索范围：[数据库/关键词]
  — 核心发现：[概述]
202X.XX-202X.XX：数据采集/案例分析阶段
  — 数据来源：[说明]
  — 采集方法：[说明]
  — 样本量/案例数：[具体数字]
202X.XX-202X.XX：数据分析/理论建构阶段
  — 分析方法：[说明]
  — 分析工具：[说明]
202X.XX-202X.XX：成果撰写阶段
  — 产出：[逐条列出]
```

**Step 2：研究方法说明**
对每个方法的说明遵循"是什么→为什么→怎么用"三段式：
1. 方法是什么？（简洁定义）
2. 为什么选择这个方法？（与研究问题的匹配）
3. 具体怎么操作？（操作步骤+参数）

**Step 3：问题与应对**
真实记录研究过程中遇到的问题和应对措施：
- 遇到了什么困难？
- 如何调整研究设计？
- 调整对最终成果的影响？

> 💡 **研究报告特有的写作要求**：研究方法部分需要"可还原"——让读者（评审专家/管理部门）能根据你的描述判断研究是否科学、过程是否规范。不需要像学术论文那样追求论证链的严密性，但必须保证透明和可验证。

**输出产物**：研究过程梳理报告

**检查点写入**：`📁 论文输出/[项目名称]/02-研究过程梳理.md`

## 阶段三：成果整合

### 3.1 目标
将分散的研究成果整合为一个结构化的成果体系。

### 3.2 执行步骤

**Step 1：成果清单编制**
按成果类型分类整理：

| 成果类型 | 内容 | 数量要求 |
|---------|------|---------|
| 学术论文 | 已发表/已录用/在投 | 逐篇列明：标题、期刊、状态、与本项目的关系 |
| 研究报告 | 总报告 + 子报告 | 逐份列明：标题、用途 |
| 数据库/工具 | 自建数据库/分析工具 | 说明数据量、覆盖范围、访问方式 |
| 政策建议 | 被采纳/提交的建议 | 说明提交单位、采纳情况 |
| 人才培养 | 指导的学生/团队成员成长 | 学位论文、获奖等 |

**Step 2：成果与目标的对照**
以表格形式逐条对照原定目标与实际成果：

| 原定目标 | 实际完成 | 完成度 | 说明 |
|---------|---------|:--:|------|
| 目标1：XX | 成果A+B | 100% | — |
| 目标2：YY | 成果C（部分） | 70% | 因数据获取受限，调整为替代方案 |
| 目标3：ZZ | 成果D+E | 120% | 超出原定目标，新增了XX维度 |

**Step 3：创新点提炼**
从实际成果中提炼2-3个核心创新点：
- 每个创新点对应具体的成果（可查证）
- 格式："在XX方面，通过YY方法，获得/发现/构建了ZZ"
- 不得使用"首次""开创性""填补空白"（除非有正式查新报告支撑）

**Step 4：社会效益/应用价值论证**
- 学术影响：成果被引用/转载/会议报告情况
- 政策影响：建议被采纳/转化为政策文件情况
- 产业影响：成果被应用/转化为产品情况
- 社会影响：媒体报道/公众关注情况

**输出产物**：成果整合报告

**检查点写入**：`📁 论文输出/[项目名称]/03-成果整合.md`

## 阶段四：报告撰写

### 4.1 → 闸门G2（内容质量：五维评分≥35/50）

### 4.2 结构模板

根据阶段一确认的报告类型，选择对应的结构模板：

#### 模板A：课题结题报告

```
一、项目概述
  1.1 项目基本信息（名称/编号/来源/周期/经费/负责人）
  1.2 项目背景与意义（2-3段）
  1.3 研究目标与内容（原定+调整说明）

二、研究工作主要进展
  2.1 理论研究进展
  2.2 实证研究/案例分析进展
  2.3 方法创新（如有）
  （按原定研究内容的顺序逐项对应）

三、主要研究成果
  3.1 学术论文（逐篇列明，标注与本项目的对应关系）
  3.2 研究报告（总报告+子报告摘要）
  3.3 数据库/案例库/工具（说明内容与功能）
  3.4 政策建议/咨政报告（说明采纳情况）
  3.5 人才培养

四、成果的创新点与学术价值
  4.1 创新点一：XX（对应具体成果）
  4.2 创新点二：XX（对应具体成果）
  4.3 学术价值（对学科/领域的推进）

五、成果的应用价值与社会效益
  5.1 应用价值
  5.2 社会效益
  5.3 成果转化情况（如有）

六、存在问题与改进方向
  6.1 研究中存在的问题（客观、诚实）
  6.2 改进方向（可操作的后续计划）
  6.3 对相关领域研究的建议

七、经费使用情况
  7.1 预算执行总览
  7.2 分项支出说明
  7.3 结余/超支说明（如有）

八、附件材料
  8.1 代表性成果复印件/扫描件
  8.2 采纳证明/应用证明
  8.3 其他支撑材料
```

#### 模板B：项目研究报告（横向/纵向交付）

```
一、项目背景与目标
二、研究设计与方法
三、研究过程（按阶段或任务线）
四、主要发现与分析
五、结论与建议
六、附录（数据表/调查问卷/访谈提纲等）
```

#### 模板C：调研报告

```
一、调研背景与目的
二、调研对象与方法
三、调研发现
四、问题分析
五、对策建议
六、附录（调研工具/原始数据摘要）
```

#### 模板D：年度进展报告

```
一、本年度主要工作
二、阶段性成果
三、存在的问题
四、下一年度工作计划
五、经费使用情况（年初至报告期）
六、附件
```

### 4.3 撰写要点

**语言风格**：
- 比学术论文更直接、更务实——面向管理者而非同行学者
- 判断句开段保留（殿主文风特征）
- 禁用"本文""笔者"（以判断句直接开段）
- 禁用AI味套话（执行五层去味系统）
- 数据必须具体、可核实

**特殊要求**（研究报告专属）：
- 每一项成果必须对应到原定目标（可追溯）
- 每一个"未完成"必须说明客观原因（诚信）
- 经费数据必须准确（与财务数据一致）
- 成果列表必须有证明材料支撑（不可空列）

**文风要求**（报告态）：
- 启用文风指纹特征2（判断句开段）+ 特征4（三段式结构）+ 特征7（辩证张力）
- 不启用特征1（长句链）——研究报告需要更高的可读性
- 不启用特征3（设问自答）——报告面向管理而非学术对话
- 不启用特征5（段落递进链）和特征6（数据三步法）——报告结构由模板固定

### 4.4 文风过渡段

> 研究报告的文风位于"学术论文的严谨"与"工作报告的精炼"之间——既不能过于学术化（评审专家不全是同学科），也不能过于通俗化（需要体现研究的专业性）。核心原则：**可读性优先于修辞华丽度，可查证性优先于理论深度。**

### 4.5 闸门G2：内容质量判定

**判定标准**：

| 检查项 | 标准 | 不通过时的输出 |
|--------|------|-------------|
| 五维评分 | ≥35/50 | 「G2不通过：五维评分[XX]/50，以下是丢分项分析……」 |
| AI味禁用词 | ≤3次/千字 | 「G2不通过：检测到[X]处AI味表达，请定向清理……」 |
| 结构完整性 | 所有必填章节完整 | 「G2不通过：缺失[XX]章节，请补全……」 |
| 数据准确性 | 成果数量、经费数字与实际一致 | 「G2不通过：[具体数据项]与原始材料不符……」 |

**不通过时的行动**：回到阶段三（如果数据缺失）或执行五层去味管线Layer 2-4深度清理（如果AI味超标）。

**输出产物**：完整研究报告初稿

**检查点写入**：`📁 论文输出/[项目名称]/04-报告初稿.md`

## 阶段五：审校打磨

### 5.1 → 闸门G4（格式合规终审）

### 5.2 审校清单

| 检查项 | 具体标准 | 不通过后果 |
|--------|---------|----------|
| 结构完整性 | 按选定模板，所有必填章节完整 | 退回补全 |
| 数据一致性 | 全文数据前后一致（成果数、经费、时间等） | 退回核实 |
| 成果可查证 | 每一项成果声称有对应证明材料 | 标记需补材料 |
| 匿名性（如需） | 盲审版本无身份信息 | 退回脱敏 |
| 参考文献格式 | GB/T 7714-2025 | 退回修正 |
| 字数合规 | 各报告类型有不同要求 | 退回调整 |
| 五维评分最终检查 | ≥35/50 | 退回去味 |
| 附录完整性 | 所有引用的附件均已纳入 | 标记需补附件 |

### 5.3 字数参考

| 报告类型 | 建议正文字数 | 不含附件 |
|---------|------------|---------|
| 课题结题报告 | 8000-15000字 | 附件另计 |
| 项目研究报告 | 5000-12000字 | 视项目规模 |
| 调研报告 | 3000-8000字 | 视调研范围 |
| 年度进展报告 | 2000-5000字 | 简明扼要 |
| 成果总结报告 | 3000-6000字 | 突出亮点 |

### 5.4 闸门G4：格式合规终审

全部检查项通过 → G4通过 → 输出交付就绪报告。

**输出产物**：
- 研究报告终稿
- 格式合规报告
- 成果对照清单

**检查点写入**：`📁 论文输出/[项目名称]/05-报告终稿.md`

## 附二：与其他三种模式的关键差异

| 维度 | 论文模式 | 课题申报模式 | 评论模式 | **研究报告模式** |
|------|---------|------------|---------|---------------|
| 时间朝向 | 当下 | **未来**（前瞻） | 当下 | **过去**（回溯） |
| 逻辑起点 | 学术前沿 | 政策需求 | 社会热点 | **立项承诺** |
| 核心任务 | 深度论证一个问题 | 说服评审专家"值得资助" | 学术视角大众表达 | **证明"我完成了承诺"** |
| 语言风格 | 学术论证（长句链） | 政策语言+学术 | 学术素养+大众表达 | **精炼务实（面向管理者）** |
| 字数范围 | 8000-12000 | 4000-7000 | 1000-3000 | **3000-15000（视类型）** |
| 关键红线 | 原创性+论证严密 | 匿名性+政策契合 | 观点有学术底色 | **成果可查证+数据准确** |
| 评审逻辑 | 同行评议 | 国社科评审标准 | 读者反馈 | **目标-成果对照** |
| 文风重点 | 七大特征全部 | 特征2/4/7 | 叙事骨架 | **特征2/4/7（不含长句链）** |
