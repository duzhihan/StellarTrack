# 论文模式 — 完整执行指南

> 本文档是论文工厂「论文模式」的详细执行手册
> 调用方：SKILL.md 中"模式二：论文模式"的流水线
> 执行方式：逐阶段推进，每阶段结束后必须经过质量闸门判定

---

## 质量保障策略

论文模式采用**三层递进式质量保障**：

| 层级 | 闸门 | 检查内容 | 性质 |
|:--:|------|---------|------|
| L1 形式质量 | G2 | 五维评分（直接性/节奏/可信度/真实感/信息密度≥35/50）、AI味密度≤3次/千字、字数合规、章节连贯性 | 撰稿后的出厂质检（形式层面） |
| L2 学术质量 | G3 | 多Agent审稿（7Agent）+ 5维评审 + 4层分级诊断 | 学术评审（内容层面） |
| L3 格式质量 | G4 | GB/T 7714-2025全量检查 | 投稿前的格式终审 |

**与其他模式的差异**：论文模式是论文工厂最重的质量保障模式——G2+G3+G4三闸门覆盖形式→内容→格式全链路。这是因为CSSCI期刊投稿的容错空间最小，审稿周期最长，必须在提交前最大化发现问题的概率。

## 阶段一：选题综述

### 1.0 知网选题加工节点（人机交互）

> **何时触发**：殿主进入论文模式，无论是明确选题还是模糊方向，均建议先执行此节点以充分利用知网平台的专业评测资源。殿主可选择跳过（直接进入1.1.1）。

**节点性质**：本节点是论文工厂内置的**人机接力暂停点**。系统暂停自动推进，殿主前往知网选题平台亲自操作完成三项任务，再将结果返回论文工厂。

#### 第一步：启动暂停 — 指引殿主前往知网平台

系统输出以下指引：

```
⏸️ 【知网选题加工节点】

请前往知网选题评测平台完成以下三项任务，完成后将结果粘贴回来，供系统继续处理。

🔗 平台地址：https://x.cnki.net/web/topic/?platform=yxpt#/topicRecommend/index

---

📌 任务一：定题测评
  - 在平台中输入您的选题方向/初步标题
  - 完成"选题可行性评测"（知网AI会给出创新度、发表可行性等维度的评分和建议）
  - 记录评测结果（截图或复制文字均可）

📌 任务二：标题打磨
  - 利用平台的"标题优化"功能，对初步标题进行多版本打磨
  - 记录平台给出的3-5个优化标题备选方案及各方案的建议理由

📌 任务三：综述辅助
  - 利用平台的文献综述/选题综述功能，获取该方向近年核心文献概况
  - 复制或概括平台生成的综述摘要（不需要完整，关键信息即可：主要文献/研究现状/研究空白）

完成后，请将三项结果以如下格式返回：

---
【定题测评结果】
（粘贴或概括评测报告内容，包含评分维度和关键建议）

【标题打磨结果】
（列出平台给出的备选标题方案，3-5个）

【综述结果】
（粘贴或概括平台生成的综述内容）
---

⏯️ 收到您的返回结果后，系统将自动继续推进阶段一。
```

#### 第二步：接收并处理返回结果

殿主返回三项结果后，系统执行以下处理：

**处理定题测评结果**：
- 提取知网平台给出的评分维度（创新度/发表可行性/研究空白等）
- 识别平台建议的调整方向
- 将评测结论作为后续G1闸门判定的**外部参照权重**（知网平台评分≥4/5视为高可行性信号，可在G1判定中加权处理）

**处理标题打磨结果**：
- 分析平台给出的备选标题，按以下维度评估：
  - 理论术语的辨识度（是否含有学科核心概念）
  - 研究切口的清晰度（是否体现具体的研究对象/视角）
  - 期刊适配度（与殿主目标投稿期刊的标题风格是否匹配）
- 与系统自生成的选题候选合并，供殿主最终选择
- 输出：标题优选推荐（从平台方案+系统方案中各选1-2个，附简短理由）

**处理综述结果**：
- 将平台综述作为文献调研的**起点底稿**，不完全替代系统深研
- 识别平台综述中已覆盖的研究脉络 vs 尚未触及的理论对话资源
- 生成"补充调研清单"：列出平台综述未覆盖但殿主研究方向需要的理论资源（优先涵盖中西方理论对话资源）
- 如殿主已对平台综述内容满意，可选择跳过1.1.2（直接从平台综述跳到1.1.3大纲生成）

#### 入口条件更新

根据殿主返回结果的完整程度，动态调整阶段一起点：

| 殿主提供的内容 | 系统推进逻辑 |
|-------------|------------|
| 完成三项任务并返回全部结果 | 处理返回结果 → 跳转至1.1.1（整合平台数据+系统选题）|
| 仅返回"定题测评"和"标题打磨"，无综述 | 处理前两项 → 1.1.2自动补充文献调研 |
| 仅返回综述结果 | 以综述为基础 → 直接从1.1.3大纲生成开始 |
| 殿主跳过知网节点（说"跳过"或"不用") | 进入传统流程，从1.1.1选题导航或1.1.2文献调研开始 |
| 殿主已有完整大纲 | 跳过整个阶段一，进入阶段二 |

---

### 1.1 入口条件（传统路径/知网节点后的后续路径）

- **明确选题**：殿主已指定论文标题和研究方向（或来自知网平台打磨后的标题）→ 跳过1.1.1选题导航，从1.1.2文献调研开始（或跳过1.1.2直接进1.1.3，如已有平台综述）
- **模糊方向**：殿主仅给出大致方向 → 先执行1.1.1选题导航（如已有平台评测结果，将结果注入选题导航作为参照）
- **已有文献调研**：殿主已提供文献调研报告（含平台综述）→ 跳过1.1.2，从1.1.3大纲生成开始
- **已有完整大纲**：殿主已提供完整大纲 → 跳过整个阶段一，进入阶段二

### 1.1.1 选题导航（模糊方向时触发）

**执行步骤**：

1. 加载 `references/editor-prompts.md` 中的 **模板1：选题生成器**
2. 将殿主的研究方向填入模板的 Input 字段
3. 按照模板的四步思考框架（学术前沿定位 → 研究范式分配 → 三层论证设计 → 发表可行性筛选），在后台进行分析
4. 输出：8-10个选题方案（按模板的三字段格式）+ 选题覆盖说明
5. 等待殿主选择1个选题（或指定方向继续聚焦）

**调用资源**：
- 主Prompt：`references/editor-prompts.md` 模板1（选题生成器）
- 辅助数据：`references/prompt-index.md` 中I-01~I-05（文献检索辅助）
- 底层引擎：`deep-research`（如需系统性文献调研支撑选题判断）

**输出产物**：选题方案列表（等待殿主选择）

### 1.1.2 文献调研与创新点提炼（选定选题后）

**执行步骤**：

1. 调用 `deep-research`，以选定选题为核心搜索词
2. 研究方向：系统性检索CNKI和WOS中最近5年的相关文献
3. 提取：核心文献列表、研究脉络、理论对话资源、方法论趋势
4. 对照 `references/editor-prompts.md` 模板1中的"研究空白识别"维度，识别3-5个研究空白
5. 对每个空白评估：新颖性(1-5)、重要性(1-5)、可行性(1-5)
6. 提炼2-3个创新点（每个创新点用"做了X"句式，可验证）

**调用资源**：
- 主引擎：`deep-research`（13-Agent深度研究模式）
- 辅助指令：`references/prompt-index.md` 中I-02（文献快速总结）、I-03（多篇文献对比）、I-04（研究空白识别）
- 副Prompt：`references/editor-prompts.md` 模板1（Step 3：三层论证设计中的创新判断标准）

**输出产物**：文献调研报告 + 创新点声明

### 1.1.2b 文献综述撰写（嵌入离朱，可选但强烈推荐）

**目标**：将文献调研报告加工为"问题驱动"的引言+综述段落（问题锚定→理论框架→文献评述→研究缺口→模型建构），直接作为 1.1.3 大纲生成和阶段二撰稿的输入。**全程零切换，不要求殿主介入。**

**执行方式**：加载 `literature-review-writer`（离朱·文献综述）的规则文件，按嵌入协议执行：

1. 加载 `../literature-review-writer/references/stage1-intro.md` → 引言漏斗：从选题切入（现象矛盾/政策背景/理论缝隙三选一），引入权威理论判断锚定问题，凝练一句话核心研究问题
2. 加载 `../literature-review-writer/references/stage2-theory.md` → 理论框架定位：选一个"贴身"核心理论 + 1-2 补充理论，判断价值与不足
3. 加载 `../literature-review-writer/references/stage3-classify.md` → 文献分类与评述：按问题维度分类，每类"主题句→文献整合→批判分析→过渡衔接"，述4评6，识别观点冲突
4. 加载 `../literature-review-writer/references/stage4-gap.md` → 研究缺口定位：从文献调研报告的 3-5 个空白中收敛为 1-2 个核心缺口，表述为"从 A 和 B 均未回答 Y"
5. 加载 `../literature-review-writer/references/stage5-model.md` → 模型建构与操作化：创新点落为 2-3 个可检验假设（H）或研究问题（RQ）
6. 加载 `../literature-review-writer/references/stage6-writing.md` → 整合成稿：按"引言漏斗→模型建构→理论框架+文献评述→研究缺口"顺序成文，字数分配引言20%/主体50%/述评30%

**产出校验**：加载 `../literature-review-writer/references/selfcheck.md` 的 14 项自检清单核查（关键项：问题锚定/理论框架/研究缺口/操作化必须通过）。

**输入**：文献调研报告 + 选题 + 殿主目标期刊信息
**输出产物**：引言+文献综述段落（约 800-1500 字，随正文体量缩放）+ 核心问题一句话 + 假设/RQ 清单

> **跳过条件**：殿主明确说"不写综述"或已有成熟综述段落时跳过；若仅需创新点声明，1.1.2 已产出，本环节可简化执行。

### 1.1.3 大纲生成

**执行步骤**：

1. 加载 `references/editor-prompts.md` 中的 **模板2：大纲生成器**
2. 将以下输入填入模板：
   - 选定选题（标题+研究方向）
   - 文献调研报告
   - 创新点声明
3. 严格按照模板的五段输出格式（预写摘要→引言→理论框架→核心三章→结论与讨论）
4. 特别注意：理论框架必须是**原创性整合**（不能是对已有理论的简单复述）
5. 检查"引言-结论镜像对称"：结论中的每个点是否回应了引言中的承诺

**调用资源**：
- 主Prompt：`references/editor-prompts.md` 模板2（大纲生成器）
- 辅助指令：`references/prompt-index.md` 中II-01~II-05（各章节写作辅助）、II-08（摘要生成）、II-10（标题生成）
- 格式规范：GB/T 7714-2025

**输出产物**：完整论文大纲（含预写摘要、理论框架、核心章节论述方向）

### 1.1.4 闸门G1：选题论证评审

**判定标准**：
| 维度 | 评分(1-5) | 判定 |
|------|----------|------|
| 创新性 | ___ | ≥3 通过 |
| 可行性 | ___ | ≥3 通过 |
| 理论框架原创性 | ___ | ≥3 通过 |
| 大纲逻辑完整性 | ___ | ≥3 通过 |

**判定逻辑**：
- 四项全部 ≥3 → G1通过，进入阶段二
- 任一项 <3 → G1不通过，输出：「G1不通过：[具体维度]评分为[X]/5，问题：[具体问题]。建议方案：[调整方向]。请修正后重试。」

**输出产物**：G1通过报告（含四项评分）

**检查点写入**：
```
📁 论文输出/[项目名称]/
  └── 01-选题方案.md   ← 写入（选题论证+文献地图+创新声明+大纲+G1报告）
```

**➡️ 下一步**：G1通过 → 自动进入阶段二（类文风撰稿）。如需先审阅大纲，说"暂停，我先看看大纲"。

## 阶段二：类文风撰稿

这是整套系统最有殿主辨识度的核心模块。

### 2.1 撰稿原则

在开始撰写之前，必须加载以下两份文件作为强制约束：

1. `references/style-fingerprint.md`（文风指纹库——告诉你"应该怎么写"）
2. `references/ai-vocabulary-filter.md`（五层清稿管线——执行Quick Checks→短语黑名单→结构反模式→虚假施动者→五维评分的全链路去味）

撰稿过程中，七大文风特征必须贯穿始终。不是"写完后调整"，而是"写着就带着"。

### 2.2 撰稿流程

#### 第一步：加载大纲和文风指纹

```
输入：
- 阶段一产出的大纲（含预写摘要、理论框架、各节论述方向）
- references/ai-vocabulary-filter.md（五层清稿管线：Quick Checks→短语黑名单→结构反模式→虚假施动者→五维评分）
- references/style-fingerprint.md（七大特征+量化参数）
```

#### 第二步：按章节顺序逐节撰写

**撰写顺序**（不是从第一章开始写，而是按论证重要性排序）：
1. **理论框架**（最先写——这是整篇论文的核心竞争力，写好后作为后续全部章节的"锚"）
2. **核心三章**（按论证递进顺序，先现象→后机制→最后意义）
3. **引言**（正文写完后写——只有正文写完了，才知道引言该怎么"引"）
4. **结论与讨论**（引言之后写——回应引言+总结正文）
5. **摘要**（最最后——全文写完后提炼）

**每节撰写时的强制操作**：

1. 回顾该节在大纲中的"论述方向"
2. 确认该节在论证链上的"不可替代功能"（参照大纲生成器的章节功能分配）
3. 开始撰写，同时应用文风指纹：
   - 段落首句：必须为判断句（特征2）
   - 段落中间：需要时插入设问自答（特征3）
   - 段落结构：三段式（判断→机制展开→边界过渡）（特征4）
   - 句长：长句嵌入式从句链，嵌套2-4层（特征1）
   - 数据引用：三步法（判断→锚定→升维）（特征6，如涉及数据）
   - 转折：每300-500字至少1次辩证转折（特征7）
4. 写完后立即执行五层清稿管线L1-L2初步去味：检查是否使用了禁用词表中的词汇、是否有结构反模式
5. 写出"边界过渡句"（为下一节做铺垫）

#### 第三步：跨节连贯性检查

写完全部章节后，执行以下检查：
- 段落递进链检查（特征5）：连续段落之间是否形成"结构→机制→趋势"的递进？
- 禁用清单检查：是否出现了"本文""笔者""我们"？是否使用了"综上所述"？
- 简单并列检查：是否有超过3个点的并列罗列？
- 破折号检查：每500字不超过1个破折号？

### 2.3 分节撰稿的Prompt模板

对每一节，使用以下内置Prompt进行撰写：

```
# Role
你是杜智瀚老师（一位在CSSCI期刊发表过多篇论文的文艺学/艺术学理论学者）
的学术写作助手。你的任务是按照指定的大纲和文风要求，撰写论文章节。

# Task
撰写论文的【第X章：章节标题】

# Context
完整大纲：[引用大纲文档]
本章在论证链中的功能：[该章解决什么问题/为什么不可被替代]

# Style Constraints（强制）
以下特征必须贯穿本节：

1. 段落首句：判断句开段（禁用"本文""笔者"）
2. 段落内部：三段式结构——判断（1-2句）→ 机制展开（3-5句）→ 边界过渡（1-2句）
3. 句长：主句嵌套2-4层从句，形成层层推进的论证链
4. 转折：每300-500字至少1次辩证转折（"但是/然而/当然/另一方面"）
5. 设问自答：必要时在段落中部嵌入（不打断论证流）
6. 引用格式：GB/T 7714-2025，脚注标注

# Content Requirements
- 本节的核心论述方向：[从大纲中提取]
- 本节必须涵盖的要点：[从大纲中提取]
- 本节与前后节的逻辑连接：[从大纲中提取]

# Forbidden
- "本文"/"本研究"/"笔者"/"我们"
- "综上所述"/"总而言之"
- 简单并列罗列超过3个点
- 破折号每500字超过1个
- leverage, delve into, elucidate, pivotal, underscore（英文引用中）
- "毋庸置疑""不可磨灭的贡献""颠覆性""深刻地"

# Output
仅输出撰写完成的正文段落，不要标注"修改"或"说明"。
```

### 2.4 调用底层引擎

在需要大量文字生成时，调用 `academic-paper`（12-Agent论文写作引擎）。但调用前，将上述风格约束作为前置指令注入——这不是让academic-paper"自由发挥"，而是让它"戴着殿主的文风镣铐跳舞"。

**注入方式**：在调用academic-paper的输入前，先加载 `style-fingerprint.md` 和 `ai-vocabulary-filter.md` 作为系统指令的前置约束。

### 2.5 撰稿输出

**输出产物**：完整论文初稿（Word/DOCX格式或Markdown格式），7大文风特征贯穿全文

**检查点写入**：
```
📁 论文输出/[项目名称]/
  └── 02-初稿.md   ← 写入（完整初稿）
```

### 2.6 闸门G2：撰稿质量自检

进入阶段三审稿之前，必须通过撰稿质量自检。

| 维度 | 判定标准 | 不通过时的处理 |
|------|---------|-------------|
| 五维评分 | 直接性/节奏/可信度/真实感/信息密度 ≥35/50 | 回到阶段二，针对丢分维度修补对应章节 |
| AI味严重程度 | 全文禁用词密度 ≤3次/千字 | 触发阶段四第一轮（AI味消除），完成后再过G2 |
| 章节连贯性 | 连续3段以上无"并列罗列"模式 | 回到阶段二，重构并列段落为递进链 |
| 字数合规 | 正文8000-12000字（±10%） | 回到阶段二，扩展或压缩 |

**G2通过输出**：
```
✅ G2通过：撰稿质量达标。
- 五维评分：[XX]/50（直接性X/节奏X/可信度X/真实感X/信息密度X）
- AI味密度：[X]次/千字
- 章节连贯性：通过
- 字数：[XXXX]字
➡️ 进入阶段三：多Agent审稿
```

**G2不通过**：逐项标注不达标项及修补目标，回到阶段二执行定向修补。

> 💡 G2是撰稿后的"出厂质检"，不是替代G3的审稿。G2只检查**形式层面的质量问题**（五维评分/连贯性/字数），G3负责**内容层面的学术评审**（论证/创新/方法）。

## 阶段三：多Agent审稿

### 3.1 前置准备

将阶段二产出的完整初稿作为输入。同时加载 `references/editor-prompts.md` 中的 **模板3：审稿系统**。

### 3.2 审稿执行

**执行步骤**：

1. 加载 `academic-paper-reviewer`（7-Agent多视角审稿引擎）
2. 同时注入 `references/editor-prompts.md` 模板3（审稿系统）的思考框架
3. 7个Agent并行审稿：
   - 主编Agent：统筹审稿流程，综合评审意见
   - 审稿人A（方法论专家）：重点审查研究方法和论证逻辑
   - 审稿人B（领域专家）：重点审查理论深度和文献对话
   - 审稿人C（跨学科视角）：重点审查跨学科贡献和创新性
   - 魔鬼辩护人（DA）：最严厉的批判性审查
   - 协调Agent：量化打分
   - 验证Agent：事实核查（引用准确性）
4. 综合评分：0-100分制

### 3.3 额外检查维度（人文社科专属）

在academic-paper-reviewer的标准维度之外，增加以下检查：

| 检查项 | 判定标准 |
|--------|---------|
| 理论对话深度 | 是否与至少3个不同的理论传统形成实质性对话？ |
| 论证逻辑严密性 | 核心论点的每一步推导是否可追溯？ |
| 文献覆盖全面性 | 近3年CSSCI核心文献覆盖率？ |
| 文风一致性 | 七大文风特征在全文中的贯穿度？ |
| 人文社科发表匹配度 | 目标期刊的选题偏好和研究范式是否匹配？ |

### 3.4 闸门G3：评审通过判定

**判定标准**：
- 综合评分 ≥ 60/100 → G3通过，进入阶段四
- 综合评分 < 60/100 → G3不通过

**不通过时的输出**：
```
G3不通过：综合评分 [XX]/100 [第N/3轮]

【四层分级诊断】
[按照模板3的四层分级格式输出全部问题]

【修改路线图】
1. 优先解决致命性问题（[N]项）
2. 其次解决高优先级问题（[N]项）
3. 再次优化中优先级问题（[N]项）
4. 可选优化低优先级问题（[N]项）

⏳ 剩余审稿机会：[3-N]次
```

> ⚠️ 审稿-修改循环上限为3次。第3次G3仍不通过时，系统标注为"高风险稿件"，建议殿主重新审视选题方向或考虑调整研究方法。

### 3.5 输出产物

**通过**：评审通过报告（含评分 + 总分维度得分）
**不通过**：四层分级评审报告（致命→高→中→低）+ 修改路线图

**检查点写入**：
```
📁 论文输出/[项目名称]/
  └── 03-评审报告.md   ← 写入（G3评审报告+评分+路线图）
```

**➡️ 下一步**：G3通过 → 自动进入阶段四（逐段修改）。G3不通过 → 进入内循环（修改→再审，最多3轮）。

## 阶段四：逐段修改

### 4.1 修改引擎

以**嵌入模式**调用 `杜智瀚改论文`（v3.2，Hub-and-Spoke 重构版）——**直接加载其规则文件执行，不调用其 SKILL.md 入口**（避免触发模式选择询问打断流水线）：

| 规则文件 | 用途 | 优先级 |
|---------|------|--------|
| `../duzhihan-paper-editor/references/global-diagnosis.md` | 全局诊断规则 | 第一轮执行 |
| `../duzhihan-paper-editor/references/paragraph-edit.md` | 逐段修改规则 | 第二轮执行 |
| `../duzhihan-paper-editor/references/writing-sop.md` | 五阶段方法论 | 底层依据 |
| `../duzhihan-paper-editor/references/style-rules.md` | 杜智瀚文风规则 | **最高优先级** |
| `../duzhihan-paper-editor/references/csci-standards.md` | CSSCI规范+修改原则 | 规范约束 |

> ⚠ 嵌入原则：全程自动执行，不询问模式、不要求用户介入、不输出"是否继续"。用户无需知道本阶段调用了哪个 skill。

### 4.2 修改流程

**第一轮：全局诊断**
- 输入：完整初稿 + 阶段三的评审报告
- 执行：按 `global-diagnosis.md` 规则执行（理论适用性→案例价值→标题→摘要→结构→三大问题→重复检测→结构重组→宏观论证逻辑）
- 产出：全局诊断报告（标题+结构+摘要+三大问题+重复检测+结构重组）

**第二轮：修改执行**
- 按 `paragraph-edit.md` 规则逐条修改（6.2 修改核心原则：语义关联度决定合并拆分 / 章节标题强制诊断 / 修改透明度；6.3 输出格式模板；6.5 作者风格保护原则）
- 针对全局诊断和审稿报告中的每个问题，逐条修改
- 加载 `references/editor-prompts.md` 中的 **模板4：修改建议生成器**
- 每个修改遵循"可写入"标准（修改后的文本可直接复制粘贴）
- 涉及作者风格保护项的操作，标注"⚠ 作者风格保护项：[说明]"

**第三轮：五层清稿管线全层执行**
- 加载 `references/ai-vocabulary-filter.md`（五层清稿管线）
- 全文依次执行：
  - Layer 1 Quick Checks：删冗余副词、元评论句、宣布动作、控破折号、删机械连接词
  - Layer 2 短语黑名单：全文扫描中英文禁用词并替换
  - Layer 3 结构反模式：检测Binary Contrast、Tripling、Punch Line、Rhetorical Setup、Meta-Joiners
  - Layer 4 虚假施动者：检查"数据表明""研究显示"等无来源断言
  - Layer 5 五维评分：目标≥40/50
- 对每个检测到的问题，逐一处理

**第四轮：文风终校**
- 对照 `references/style-fingerprint.md` 七大特征
- 逐段检查：判断句开段、三段式结构、辩证转折
- 对不达标的段落进行修改

### 4.3 修改原则

- **宁缺毋滥**：如果原文已足够好，不强行修改
- **尊重作者意图**：修改不改变核心论证方向
- **可写入优于可参考**：每个修改建议给出具体替换文本

### 4.4 输出产物

终稿（经过四轮修改）+ 修改日志

**检查点写入**：
```
📁 论文输出/[项目名称]/
  └── 04-终稿.md   ← 写入（终稿+修改日志）
```

**➡️ 下一步**：终稿确认后 → 自动进入阶段五（格式排版）。如需回到阶段三再审一轮，说"再审一次"。
```

## 阶段五：格式排版

### 5.1 格式检查清单

| 检查项 | 标准 | 工具 |
|--------|------|------|
| 参考文献格式 | GB/T 7714-2025（顺序编码制） | `references/prompt-index.md` 中I-05 |

| 作者信息 | 格式符合目标期刊要求 | 模板检查 |
| 图表编号 | 图1/表1连续编号 | 交叉检查 |

**检查点写入**：

## 附二：雕龙叙事在论文模式中的可选应用

论文模式可选择性注入雕龙叙事的叙事策略，增强论文的论证可读性。以下4个应用场景的详细说明见 `commentary-workflow.md` 附二：

| 应用场景 | 注入位置 | 功能 |
|---------|---------|------|
| 引言：现象切入法 | 阶段二（撰稿）引言撰写时 | 用具体案例/现象替代宏观背景开篇 |
| 论证：张力揭示法 | 阶段二（撰稿）核心章撰写时 | 用"表面A/实质B"结构组织分析 |
| 结论：读者带走法 | 阶段二（撰稿）结论撰写时 | 用金句/比喻/反问收束全文 |
| 摘要：八刀自检 | 阶段五（格式排版）前 | 用雕龙八刀检查摘要质量 |

> 注：雕龙叙事注入为可选增强模块，不启用不影响论文模式基本流水线运行。
