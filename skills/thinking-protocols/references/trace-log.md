# ② 思维轨迹档案 · 规则

> 目的：把每一次完整思考沉淀为可复盘轨迹，积累"我是怎么想的"——这是偏好画像与视角银行的事实来源。

## 何时写

**C7 交付后**（每次完整走完六环），由系统在交付消息末尾追加一段"轨迹已归档"，并写入 `data/traces/YYYY-MM-DD.md`（同名文件追加多条轨迹，按序号分隔）。

## 轨迹模板（≤250 字）

```markdown
### 轨迹 #N · YYYY-MM-DD · 问题主题

- **问题**：一句话复述
- **场景识别**：需求不明 / 需求模糊 / 复杂执行 / 正式文稿 / 研究学术
- **模式**：{模式名}（或"未选·通用基线"）｜ 是否混合
- **关键确认点**：每点用户的拍板（1-3 条最有信息量的）
- **回显结论**：本轨迹暴露的偏好（1-3 条，与画像联动）
- **新视角**：本次确认过且可复用的视角（入库视角银行）
- **交付形态**：决策指南 / 成品 / 轻思考
- **复盘标记**：值得重看？是/否（是则写一句原因）
```

## 纪律

1. **只记事实与拍板**，不记系统的分析内容（那是方案，不是轨迹）。
2. **每条 ≤250 字**——轨迹是索引，不是复述。
3. **跨次关联**：若本次与历史轨迹同主题，开头标注"关联 轨迹#M"。
4. **季度复盘**（可与偏好画像/视角银行联动）：读全部轨迹 → 提炼稳定偏好 → 更新画像 → 退役失效视角 → 规划模式训练。
5. 数据文件默认放 skill 内 `data/traces/`；若用户要求，可迁移至项目记忆或 Obsidian 知识库（迁移后更新路径说明）。
