# 苏格拉底追问

## 目的

当用户需求模糊时，通过**一次一问**的追问链，把"模糊意图"收敛为"可执行的具体需求"。不替用户想，只引导用户自己想清楚。

## 触发信号

- "帮我弄个方案"（没说主题）
- "写个东西"（没说写什么）
- "整理一下"（没说整理什么）
- "做个分析"（没说分析对象）

## 追问铁律

1. **一次只问一个问题**——绝不抛"你有几个问题"式清单
2. **顺着上一答追问**——答案决定下一问，不跳问
3. **问到 95% 信心即停**——能开始执行就停，不追求 100%
4. **不替用户预设答案**——不把"你是不是想要 X"当问句（那是诱导）

## 追问链（默认顺序，按需裁剪）

| 层 | 问什么 | 目的 |
|----|--------|------|
| 1 | 这个方案/文章/分析，最终要达成什么效果？ | 锁定目标 |
| 2 | 给谁看/给谁用？ | 锁定受众 |
| 3 | 现在手头有什么材料/信息？ | 锁定起点 |
| 4 | 有没有特别的偏好或禁忌？ | 锁定约束 |

> 用户回答已覆盖某层时，跳过该层。追问链不是固定四问，是"直到能执行"。

## 输出格式

```
【需求澄清摘要】
- 目标：[一句话]
- 受众：[谁]
- 起点：[已有材料]
- 约束：[偏好/禁忌]
- 关键假设：[信息不足处，已作合理假设]
→ 需求已澄清，交还总调度进入方案设计。
```

## 红线

- ❌ 不问无关的八卦/背景（只问影响产出的）
- ❌ 不连续问超过 4 个问题（4 个后若仍模糊，列假设并进入执行）
- ❌ 不把追问变成审问（语气保持对话感）
