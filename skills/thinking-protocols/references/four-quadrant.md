# 四象限思考

## 目的

在执行复杂任务前，用四象限清空信息死角——确保"共同已知"不打转、"我的已知你的未知"不遗漏、"我的未知你的已知"不浪费、"共同未知"不假装知道。

## 四象限

```
┌────────────────────┬────────────────────┐
│ 象限1 · 共同已知   │ 象限2 · 我的已知   │
│ 任务目标 / 已有背景 │ 你的未知           │
│ 交付标准 / 明确边界 │ 你的知识盲区       │
├────────────────────┼────────────────────┤
│ 象限3 · 我的未知   │ 象限4 · 共同未知   │
│ 你的已知           │ 无法仅靠现有信息   │
│ 主动补齐知识/风险  │ 确定的问题         │
└────────────────────┴────────────────────┘
```

## 执行步骤

### 象限 1：共同已知（先确认，不重复询问）
- 任务目标是什么？已有背景是什么？交付标准是什么？明确边界在哪？
- 若这些已清楚 → 直接进入象限 2，**不重复询问**

### 象限 2：我的已知、你的未知（识别可能遗漏的信息）
- 识别：可能影响产出的关键信息（数据缺口/语境/审美偏好/现实限制）
- 处理：**若缺失会显著改变结果 → 最多提 3 个关键问题**；若不影响 → 明确合理假设，先出探索版

### 象限 3：我的未知、你的已知（主动补齐）
- 主动补充用户可能没考虑到的知识、方法、风险、替代路径
- 若用户的前提可能错误 → **直接指出**，给出修正建议及取舍依据

### 象限 4：共同未知（转化为可验证假设）
- 识别无法仅靠现有信息确定的问题 → 转化为可验证的假设
- 必要时设计最小实验：说明要改变的单一变量、成功/失败信号、需收集的数据

## 输出格式

```
【四象限澄清】
- 共同已知：目标 / 交付标准 / 边界
- 你的未知（需你补）：[≤3 个关键问题，或已作假设]
- 你的已知（我补）：[主动补充的知识/风险/替代路径]
- 共同未知：假设清单 + 最小验证方案（如需要）
→ 边界已清，交还总调度。
```

## 红线

- ❌ 不在象限 1 重复询问已明确的内容
- ❌ 象限 2 问题不超过 3 个
- ❌ 不把象限 4 的假设当结论输出
