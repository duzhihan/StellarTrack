# ④ 视角银行 · 规则

> 目的：历次确认过的有效视角跨问题复用，越用越广——防止每次从零生成视角光谱。

## 银行数据文件

`data/perspectives/bank.md`。视角条目格式：

```markdown
### 视角 #N · {视角名}
- **类型**：利益相关者 / 时间尺度 / 空间尺度 / 抽象层级 / 领域特化
- **一句话**：从这个视角看，核心关切是什么
- **适用问题域**：决策 / 研究 / 写作 / 管理 / 关系 / 混合
- **使用记录**：轨迹#N（有效）｜ 轨迹#M（失效则移入退役区）
- **状态**：活跃 / 退役
```

## 存入时机（入库）

1. **元层视角确认后**：用户确认保留的视角 → 入库（去重：同名/同关切合并，累加使用记录）。
2. **③拆解环用户补充的视角**：用户主动补充的关键视角 → 优先入库。
3. 每条视角**最多使用 3 次标记**；被 3 个不同问题域复用 → 标记为"通用视角"（下次元层优先推荐）。

## 检索时机（出库）

1. **每次元层视角匹配前**：从银行检索同问题域 + 通用视角，作为光谱的种子，再叠加本次新生成视角。
2. 检索规则：同问题域视角优先 → 通用视角次之 → 新生成视角补充；总量仍保持 3-5 个。
3. 银行无匹配 → 正常走 meta-diagnosis 的矩阵生成流程，生成后再入库。

## 退役规则

- 连续 2 次使用被用户否决或无效 → 移入"退役区"（保留记录，不删除）。
- 季度复盘：退役区条目超过 6 个月未复活 → 删除。
