# 文风史莱姆 — 像史莱姆一样变形适配任何文风

## 核心能力

| 模式 | 触发条件 | 功能 |
|------|---------|------|
| **语境感知触发** | 写作意图检测（自动） | 检测语境→按需加载对应段→L1-L4适配输出 |
| **S-学习** | "分析我的文风""风格扫描" | Phase 1-5 渐进扫描 + 学习方案 + 迭代方案 |
| **I-识别** | "这是什么风格""文风像谁" | 15维检测 + 12原型匹配 + 五段式报告 |
| **T-迁移** | "按XX风格改写""适配XX受众" | L1词汇→L2句法→L3修辞→L4结构 分层重写 |
| **D-诊断** | "风格问题在哪""写作优化" | 缺陷定位→病因分析→紧急修复+长期训练 |

## 轻量摘要（AI 语境快速判定用）

当 AI 检测到用户当前任务为写作时，先读此摘要决定是否加载完整 skill：

```
写作任务检测 → 预估输出≥200字散文 → 判定语境 → 按需加载：
├─ 申报书语境 → 加载「语境预设库·申报书」行 + references/受众语境分类.md·申报书节
├─ 学术论文语境 → 加载「语境预设库·学术论文」行 + 杜智瀚文风档案·语境A
├─ 新媒体语境 → 加载「语境预设库·新媒体」行 + 蓝狐暗奴子模块摘要
├─ 小说语境 → 加载「语境预设库·小说」行 + 杜智瀚文风档案·语境C
├─ 其他语境 → 加载「语境预设库」对应行
└─ 用户显式说"文风史莱姆" → 全量加载（含 Phase 1-5 初始化流程）
```

## 首次加载行为

当本 skill 被加载时，首先检查工作区 `.workbuddy/memory/风格档案_{用户名}.md` 是否存在：

**若档案为空** → 向用户展示初始化提示：
> "文风史莱姆已激活。检测到尚未建立你的风格档案。要现在开始风格扫描吗？我会分析你工作区中的文本，生成学习方案和迭代方案。（预计需要 5-10 分钟）"
>
> 用户回复"开始"后，进入 Phase 1（渐进扫描）。不强制立即全量扫描。

**若档案存在** → 读取档案，进入就绪状态。根据用户当前写作任务自动适配语境。

## 触发规则

### 语境感知触发（推荐默认模式）

文风史莱姆不常驻运行。AI 在以下条件同时满足时加载：

| 条件 | 判断标准 |
|------|---------|
| 任务类型 | 用户当前对话目标包含「生成/修改/优化文本」 |
| 输出规模 | 预估输出 ≥ 100 字连贯散文（非列表/表格/代码） |
| 语境可判定 | 可从用户消息中推断出目标语境 |

加载策略：只加载与当前语境相关的段落和参考文档，不全量加载。

**不加载的情况**：
- 短问答（"是/否""可以"）
- 纯代码/数据查询
- 文件操作、命令执行
- 闲聊/问候

### 显式触发（用户唤醒完整功能）

- **史莱姆变形**："文风史莱姆""史莱姆变形"（全量加载，含初始化流程）
- **S-学习**："分析我的文风""学习风格""建立风格档案""风格扫描"
- **I-识别**："这是什么风格""文风像谁""风格归类"
- **T-迁移**："按XX风格改写""改得XX一点""适配XX受众"
- **D-诊断**："风格问题在哪""写作优化建议""看看哪里写得不好"

## 工作流

### S-学习模式：渐进扫描 + 学习方案 + 迭代方案

当用户确认开始风格学习后，按以下五阶段（Phase 1-5）执行。不要求一次性完成——支持跨对话逐批推进。

---

#### Phase 1：文本扫描与语境归档

**目标**：收集用户已有文本，按语境自动分类。

**操作步骤**：
1. 扫描工作区中所有 .md/.txt/.docx 文件 + 用户指定目录
2. 按文件名规则自动分类（参考下方分类表）
3. 每个语境选取 ≥ 1000 字的代表性样本
4. 输出语境归档清单（文件数/总字数/代表样本名）

**文件分类规则**（按文件名关键词自动判定，详见 references/受众语境分类.md）：
- "申报""课题""活页" → 申报书 | "论文""CSSCI""第X章" → 学术论文
- "新媒体""公众号""文案" → 新媒体文章 | "小说""章节""角色" → 小说
- "党建""支部""组织" → 党建申报 | "日记""随笔""闲笔" → 随笔/日记
- "汇报""总结""述职" → 工作汇报 | 无法判定 → 「待归类」

**分批策略**：若文件量 >50，分 3-5 批进行，每批一个独立对话轮次。

---

#### Phase 2：学习方案生成

**目标**：基于扫描结果，生成一份可执行的风格学习方案。

**方案结构**：

```
📋 文风史莱姆学习方案 — {用户名}

## 一、已有语境覆盖
| 语境 | 文本量 | 覆盖度 | 置信度 | 状态 |
|------|--------|--------|--------|------|
| 申报书 | 8份/2.3万字 | ★★★★★ | 高 | ✅ 就绪 |
| 学术论文 | 5份/1.8万字 | ★★★★☆ | 中高 | ✅ 就绪 |
| 新媒体 | 3份/0.6万字 | ★★☆☆☆ | 中 | 🔶 待扩充 |
| ... | ... | ... | ... | ... |

## 二、盲区诊断
- 缺失语境：[列出完全没有样本的语境]
- 薄弱语境：[列出样本不足的语境]
- 偏差风险：[某语境可能存在单一样本偏差]

## 三、学习优先级
1. 🔴 Priority-1：[最急需的语境] — 理由
2. 🟡 Priority-2：[次急需的语境] — 理由
3. 🟢 Priority-3：[锦上添花的语境] — 理由

- 立即：[下一步做什么]
- 本周：[本周计划]
- 本月：[月度目标]
```

#### Phase 3：初始风格建模

**目标**：从已扫描样本中提取风格特征，建立初始档案。

**操作步骤**：
1. 对每个覆盖度 ≥ ★★★☆☆ 的语境，运行 scripts/style_analyzer.py 批量分析
2. 跨语境对比：识别「不变核心」（跨语境稳定的风格基因）
3. 语境变量提取：对每个语境，记录相对不变核心的风格偏移
4. 原型匹配：与 references/文风原型图谱.md 进行相似度比对
5. **输出**：写入 `.workbuddy/memory/风格档案_{用户名}.md`

---

#### Phase 4：迭代方案生成

**目标**：定义风格模型的持续进化路径。

**迭代方案结构**：

```
🔄 文风史莱姆迭代方案 — {用户名}

## 反馈循环
### 对话内反馈（每次写作对话中）
- 用户说"这个风格不对" → 记录为负反馈，上下文回查调整
- 用户说"就是这个感觉" → 记录为正反馈，强化该维度参数
- 用户直接修改输出 → 对比修改前后差异，提取风格调整信号

### 档案更新（用户显式触发或对话结束时）
- 本次对话中产生的所有新文本 → 追加到对应语境库
- 风格档案的维度参数根据反馈微调
- 版本快照：档案的每次修改生成带日期后缀的副本
  - 存档路径：`.workbuddy/memory/风格档案_{用户名}_v{日期}.md`
  - 保留最近 10 个版本，支持回溯对比

## 周期性重扫（用户触发或 Automation 执行）
- 用户说"风格重扫" → 扫描工作区新增 ≥ 500 字文本，增量更新档案
- 建议使用 WorkBuddy automation 创建每周风格扫描任务
- 每季度建议生成风格演化报告（15维变化趋势）

## 退化预警（每次加载档案时检查）
- 如果一个语境超过 30 天未使用，标记为「休眠」
- 如果一个语境的风格参数连续 3 次被用户拒绝，触发重新学习
- 如果不变核心的某维度连续 2 次版本更新中评分下降 ≥ 1 分，触发深度复查
```

---

#### Phase 5：对话内持续适配

当风格档案存在后，在当前位置的对话中执行：

1. **输出前检测**：判断用户当前写作任务的目标语境
2. **按需匹配**：
   - 若档案已覆盖此语境 → 应用该语境的风格参数（L1-L4分层适配）
   - 若档案未覆盖 → 参考最相近语境参数，标记为「待学习」
   - 若档案为空 → 提示用户是否开始风格扫描
3. **本次对话追踪**：在同一对话内，记录本轮的语境切换和适配效果
4. **对话结束**：提示用户是否保存本次对话中的新文本到对应语境库

> **注意**：跨对话的持续追踪（每周重扫/风格演化报告）建议通过 WorkBuddy automation 机制实现，而非在此 skill 中假设后台运行能力。

---

#### Phase 6：初始化执行清单

当用户确认开始风格初始化时，按以下清单执行：

```
[ ] 1. 扫描工作区所有 .md/.txt/.docx 文件，提取 ≥ 500 字的文本
[ ] 2. 按语境自动分类（参考 references/受众语境分类.md 的分类规则）
[ ] 3. 对每个语境选取 Top-3 代表性样本，逐批运行 style_analyzer.py
[ ] 4. 生成「语境覆盖矩阵」（覆盖度星级 + 样本量 + 置信度）
[ ] 5. 产出「学习方案」：优先级 + 盲区 + 行动建议
[ ] 6. 建立初始风格档案（不变核心 + 语境变量表 + 原型归属）
[ ] 7. 产出「迭代方案」：反馈循环 + 重扫策略 + 退化预警
[ ] 8. 写入档案到 .workbuddy/memory/风格档案_{用户名}.md
[ ] 9. 向用户呈现学习方案摘要，询问是否调整优先级
[ ] 10. 进入语境感知触发模式
```

> 若文件量 >50，分 3-5 批进行。支持跨对话续扫——每批完成后记录进度到 memory。

### I-识别模式：风格检测与归类

对任意文本进行风格分析：

1. **快速扫描**：句长分布、标点密度、词汇层级（古/中/新/舶）
2. **深度分析**：对照 references/文风特征维度库.md 的 15 维度逐项评分（1-5）
3. **原型匹配**：与 references/文风原型图谱.md 中的原型进行相似度比对
4. **报告输出**：五段式报告——
   - 一句话风格定位
   - 15维雷达图（文本描述）
   - 最相似原型（含相似度百分比）
   - 独特性标注（哪里不像任何原型）
   - 语境适配建议

### T-迁移模式：风格应用于输出

将给定内容按目标风格重写：

1. **加载风格档案**：读取目标风格档案或语境参数
2. **识别关键特征**：从档案中提取 >=5 个必须在输出中体现的核心特征
3. **分层改写**：
   - L1 词汇层：替换不符合目标风格的词汇
   - L2 句法层：调整句长、句式结构
   - L3 修辞层：注入目标风格的修辞习惯
   - L4 结构层：调整段落组织和逻辑推进方式
4. **自检**：改完后对照风格档案逐项核验

**语境预设库**（当用户未提供具体档案时使用）：

| 语境 | 核心特征速查 |
|------|------------|
| 新媒体文章 | 短段、网感词、开头钩子、情绪高点、2-3句/段、问句驱动 |
| 党建申报 | 正式、四字格、政治站位、三级标题规范、"坚持/贯彻/落实"句首 |
| 学术论文(CSSCI) | 判断句先行、数据锚定、概念密度高、「」引观点、禁用"某学者指出" |
| 申报书 | 标识性概念、断裂诊断句、操作化路径、四要素论证、"基于……可为……"句式 |
| 评论写作 | 判断句开段、辩证收束、短句暴击、理论底牌后亮 |
| 随笔写作 | 口语化但精致、感受先行、"我"在场、散点叙事 |
| 小说叙事 | 对话推进、细节锚定、留白、感官词汇、节奏变化 |
| 工作汇报 | 条理清晰、数据说话、成果-问题-计划三段式 |

### D-诊断模式：风格优化

诊断给定文本的风格问题并给出改进方案：

1. **对照诊断**：对照 references/文风特征维度库.md 逐项评分
2. **问题定位**：识别 >=3 个具体风格缺陷（非笼统评价）
3. **病因分析**：每个问题附带成因推测
4. **改进方案**：分"紧急修复"和"长期训练"两层
5. **改写示范**：选取一段进行改写前后对比

## Python 分析脚本

`scripts/style_analyzer.py` 提供量化分析能力：

```bash
# 分析单个文本文件
python scripts/style_analyzer.py --file sample.txt --output json

# 直接输入文本分析
python scripts/style_analyzer.py --text "在这里输入文本..." --output json

# 对比两个文本的风格差异
python scripts/style_analyzer.py --compare file1.txt file2.txt
```

返回 15 维度的量化指标（L1表层5维 + L2中层5维 + L3深层5维），包括句长分布、词汇多样性、标点模式、修辞密度等。
