# 学术档工作流（科研论文 / 期刊投稿）

> **档位定位**：学术档 = 面对“学术期刊 / 同行评审”这一话语共同体时，以逻辑、创新、信息密度为质量基准的表达方式。作者身份默认 = 青年学者 / 研究者。
> **一句话**：学术档写的是“让审稿人愿意给你过”——每个判断句有出处、每个论点有支撑、每条结论能回应引言承诺。
> **母版关系**：**学术档是星躔母版**——它负载最完整的认知工序（规划/转译/修订全显式化），其他档位通过“保留 S/C1-C11 骨架、替换工序内执行方式”派生。本文件即母版执行细节的完整参考。
> **加载时机**：O2 锚定卡档位 = 学术档时，S/C1-C11 每道工序按本文件执行；其他档位派生时以本文件为对照蓝本。
> **学术锚点**：论证逻辑学（图尔敏模型）· 学术写作规范（GB/T 7714-2025）· 认知理论 informed 工程变量法（用户方法论）。

## S 论证锚定复核（学术档）

复核四要点：
1. **档位与变量匹配**：目的=论证、话语环境=学术期刊、作者身份=青年学者，是否与用户原话一致？
2. **期刊偏好**：投哪个期刊？（决定篇幅、格式、文风基调——CSSCI vs 省级，差异显著）
3. **质量标准权重**：默认六维（内容30/逻辑20/证据15/规范15/可读10/适配10，评分维度库 v2.0 现行口径），是否需调整？**（旧五维口径“逻辑40·创新25·信息密度20·可读10·合规5”已废弃，见校准台账 CL-04）**
4. **情感目标**：默认“信服/信任”——让审稿人觉得“研究重要、证据扎实、结论可信”

**档位特有复核项（S1 段）**：期刊 + 权重确认 → 进入 C1。

## C1 选题（定题四环节 · 学术档）

> **定位**：定题是第一性投资。S 层已立论证锚定（判断句/主矛盾），C1 把它验证并收敛为**定稿选题**。执行顺序以 `C1衔接协议.md` 为准：**①态势 → ②推荐 → ⑤选题确认（人机对话拍板）→ ③评测 → ④打磨**（本表按①-⑥编号，⑤“选题确认”节点须在评测前插入）。

> **引擎触发（C1 ②⑤ · 2026-10-26 补）**：**research-ideation**（乙型 · MIT · 安装位 `<技能根>/research-ideation/`）——5W1H 头脑风暴＋五类 Gap＋SMART 问题公式化＋RQ Card（假设/证据/证伪），挂②选题推荐与⑤选题确认之间；未安装或不可达须声明“未调用：research-ideation 不可达”，走本地四环节。

1. **提取 S-P 关键词**：从 O2 定稿契约 + P0 论证锚定卡提取内容领域、核心概念、判断句关键词
2. **研究态势分析**（🔴 全深度必做）：方向大盘——热度/趋势/前沿，判断值不值得做；执行方式：知网选题工具自动化（输入 S-P 关键词 → 提取态势结果 → 返回分析）或本地化检索替代
3. **选题推荐**（🟡 及以上）：从方向生成 3-5 个候选题（每个含一句话定位 + 理论锚点）
4. **定题评测**（必做）：候选题三维打分——**新颖性**（与既有研究重复度）/ **价值**（理论/实践贡献）/ **可行性**（材料可得 + 篇幅可支撑 12000-15000 字）
5. **标题打磨**（必做）：胜出题目的表达优化——遵循“理论前缀 + 冒号 + 研究对象”格式（与用户已有发表风格一致），多版本对比
6. **选题定稿**：输出选题卡 C1-xxx（定稿选题 + 四环节记录 + 评测得分 + 备选题）

**守门③（选题定稿）**：⑤选题确认已由用户拍板 + 新颖性/价值/可行性三维均过 + 标题打磨完成 → 放行 C2。
**硬性前置（R-06 · 2026-10-10 补）**：三者齐备方可通过——**三维评测达标 ＋ 用户已拍板标题 ＋ 标题打磨记录留痕**；**标题未定者，选题卡状态只能记为“草稿（挂起）”**，与守门②挂起态机制对齐（实测缺陷：标题尚为“待拍板”，守门③却已判“通过”，闸门形同虚设）。
**标题变更台账（P9 · 2026-10-10 补）**：标题**仅在 C1 步骤⑤与 C11 终校两处可改，改必留痕**；台账列“时间／版本／候选／拍板人／否决理由”，随选题卡流转。**禁模型单方拟定标题后不记录**（实测：标题四次变动均无台账）。
**深度硬标（契约 6 · v12.6.3 实测驱动）**：C1 各环节产物**按模板全字段输出**——候选清单每条必带证据链三锚＋一句话依据＋风险预判（方法卡05 产物形态）；PRQ 卡六段逐段写全（C1衔接协议 §8.7.2）；态势卡逐字段回显（热度/趋势/前沿/来源标注）；选题卡四环节记录逐项落实。**任一环节只给骨架（缺字段/缺锚/以摘要代卡）＝该工序未完成，守门不放行**——一次性带过全流程但产物全是骨架的，按未过守门处理，回补。

> **知网选题工具自动化协议（2026-08-21 实测确认）**：
> **入口**：`https://x.cnki.net/web/topic/#/topicRecommend/index?model=tencent_origin_deepseek_v4_pro_think`（AI 选题分析）
> **登录**：知网研学账号（账号密码或扫码均可）；登录态保存在浏览器会话（cookie），同会话复用
> **开工三查（会话前置，硬性）**：任何知网原生通道操作（选题工具/kns 检索/详情页补读）开工前依次核查——①调试端口存活：`curl http://127.0.0.1:9222/json/version` 有响应；②知网登录态有效：打开页面确认非扫码页；③**向用户显式提醒“检索期间请勿关闭原 Chrome 窗口”**。任一项不通，先报告环境问题并给出修复步骤（如以 `--remote-debugging-port=9222 --user-data-dir={专用持久化目录}` 拉起独立实例），禁止闷头检索空耗时间。独立实例的 user-data-dir 用固定持久化目录，登录一次后续会话复用。
> **三查须回显为产物字段（R-01 · 2026-10-10 补）**：三查结果（①端口状态 ②登录态 ③勿关窗提醒）**必须写入选题卡固定字段**——**未回显者不得进入降级分支**；降级须标注“降级：原因＋三查结果”。理由：三查此前是“要求”而非“必经产物”，**无产物即无闸门**，模型可凭一句假设跳过并静默降级（实测缺陷 P1）。
> **能力判据以本会话为准（R-07 · 2026-10-10 补）**：判定浏览器能力时，**必须回显本会话实际可用的工具清单**，**不得以 `mcp.json` 等配置文件状态代替**；未加载时报“**需重载宿主**”，**禁止**表述为“本宿主无此能力”（实测缺陷 F-08：配置已启用但会话未加载，被说成能力缺失）。
> **跨宿主注记**：①中的 curl 调试端口检查仅适用于有 shell 执行能力的宿主；无 shell 宿主改用 `cnki-deepsearch` §1.1 环境分类法（A 有有头浏览器工具／B 有 cnki-browser 类 MCP／C 无）判定浏览器能力，不自检调试端口。C 类不卡死——转本地化四环节并标注降级。

## C2 材料建档（证据账本）

> **证据账本**（概念）：借会计账本意象——每笔进出有凭据。把每个核心判断句登记在册、对应到具体证据，让“我觉得对”变成“账上有据”。

1. 从**定稿选题卡**生成检索关键词（领域×核心概念×理论锚点）
2. 执行检索：用 cnki-deepsearch（知网三层检索）；全深度（≥1月）发起后台子代理并行采集，主会话不阻塞
3. **建立证据账本**：

```markdown
| 判断句编号 | 判断句 | 证据条目 | 证据类型 | 可信度 | 与论点关系 |
|---|---|---|---|---|---|
| J01 | {核心判断} | {出处+引文要点} | 文献/数据/案例/政策 | 高/中/低 | 支撑/反证/背景 |
```

4. 材料不足时：研究/追问/缩短，**绝不用重复解释灌字数**
5. **承重文献五层拆解（v12.6.1 补 · humanities-thesis-skill 蒸馏 · MIT）**：对 3-5 篇承重文献按五层榨取——①**元信息**（标题/作者/论点/方法/关键词）②**论证结构**（问题→立场→论证路径→结论）③**证据与引文标记**（可引用论点/数据/方法，附页码）④**与本文关系定位**（理论基础/对话对象/反面论据）⑤**交叉比对**（多篇间共识/分歧/空白）。与证据账本三字段互补：账本记“有没有”，五层拆解回答“怎么用”。

**守门④**：判断句-证据覆盖率 ≥80% 且关键论点有高可信度证据 → 放行。

## C3 综述（纯综述 · 综述引擎引擎 · 学术档）

1. 输入：证据账本/综述总成卡（C2 产物）；确定模式——**M1 嵌入式**（期刊论文综述节，1500-3000字）/ **M2 完整式**（申报书完整综述，5000-8000字）
2. **开工首步挂载声明（强制 · v12.6.3 实测断点修复）**：声明 literature-review-writer 综述引擎挂载状态——①可用 → 正常挂载（归类两遍法→评述成文（段落循环四件套，述4评6）→缺口收束）；②未安装/知网通道不可达 → **显式声明”降级 C3·原因X”**＋走材料来源纪律（见下）；**未声明即开工 → 守门⑤ 不放行**（C-10 强制触发的 C3 落地）。
   **综述材料来源纪律（v12.6.3 补 · 堵”网上资料直接写”）**：综述正文**每条承重命题必须有 C2 A-LIT 池可回查题录（asset_id）支撑**；外部/公开检索材料（含 WebSearch）**必须先入 C2 账本**（走 C2 建档流程，标注来源分级：一级承重/二级辅助）再进综述；**禁止”网上资料直接写”**——未经建档材料进入综述正文＝静默降级，守门⑤ 硬不放行，回 C2 补建档后重入。
3. **缺口是论证结论而非检索转写**：四类评述合观推导；M2 增查”谱系完整性””研究趋势研判”
4. **期刊画像预学习**：按 journal-prelearn 协议消费目标刊画像（缺失则补建）——引言定稿的对照依据在 C4/C6 使用
5. 产出：综述稿+**缺口卡** C3-xxx（C3→C4 接口件）

**守门⑤**：承重席全覆盖、强缺口表述、评分维度库打分 ≥7 → 放行。
- **守门⑤ 增补四句（v12.6.1 · 综述深度与准确性）**：
1. **删作者名测试**：段落删去所有人名后仍能说清领域研究进展者放行；只剩“A 说 B 做 C 发现”者打回（来源：抖音文献矩阵五列法）
2. **逐源批判性七问**：每篇承重文献至少答出三问——论点是什么？论据是否支撑？与相邻文献矛盾处？遗漏或误解？局限？与本文契合度？方法正当性？（来源：QUT cite/write）
3. **证据强度三标**：承重文献按 A（方法透明＋高被引）／B（单一研究＋结论有限）／C（观点性或证据弱）分类标注，**C 级不得单独支撑缺口表述**（来源：literature-review skill 证据分级思想）
4. **检索留痕三行**：M2 完整式强制登记——检索串＋检索日期＋各阶段命中数（识别/去重/题摘/全文/纳入），缺行即报告不完整（来源：PRISMA 2020 转译）
5. **防幻觉硬规则 R1-R4（v12.6.1 · humanities-thesis-skill 蒸馏 · 写在任何写作指导之前的纪律）**：**R1 不编造文献**（引用必有实存来源，查不到写”未能核实”）｜**R2 不虚构引文**（引文逐字可核对，禁”大概意思”式转述冒充引文；英文引语一字不改）｜**R3 不捏造数据**（承重数字必有来源）｜**R4 前置声明**（开写前先声明本稿防幻觉纪律；检索留痕三行随行，防幻觉规则优先于任何写作指导）
6. **综述材料来源硬检（v12.6.3 补 · 实测断点修复）**：综述全部承重命题来源覆盖率 **100% 可回查**（asset_id 或题录）；任一承重命题无来源支撑 → 该段判“薄弱综述段·来源缺失”，回 C2 补建档后重入；**产物头部须声明综述材料基线**（知网通道／用户粘贴／公开学术检索 三选一＋降级标注“降级 C3·原因X”）——**无基线声明不放行**（堵“网上资料直接写”）
7. **深度硬标（契约 6 · v12.6.3 实测驱动）**：综述按引擎协议**述4评6、归类两遍法逐段执行**；缺口卡三条件（具体/可验证/有后果）逐条自检并回显；检索留痕三行随行。**只给骨架（罗列人名无评述／缺检索留痕／缺口卡三条件缺一）＝该工序未完成，守门不放行**

## C4 论证·整体框架（学术核心竞争力）

1. **理论框架定位**：核心理论域识别 +“价值与不足”判定（“X 可以解释 A，但难以阐明 B 的 C 维度”句式）+ 辅助理论批判性补充（非并列堆放）
2. **概念收敛与模型**：核心概念 ≤3（新概念附谱系定位）+ 机制模型（传导句式：X 通过 Y 实现 Z）+ RQ 三维递进链/H 因果链
2b. **段落五元组预分配（方法卡13）**：大纲给每个规划段落预分配——读者功能/承重主张/授权证据/推理边界/过渡桥；与素材分配表并行产出（五元组管论证角色，素材表管材料落位）。**nonclaims 预登记（v12.6.1）**：大纲同时登记“本文明确不主张什么”（架构期登记，写作期不再防御性声明——与 C6 作者姿态/anti-defensive 联动，防防御性写作后置爆发）
3. **全文骨架确认**：节次方案卡（GATE 用户选定）；大纲五要素映射（预写摘要→引言→理论框架→核心章→结论）；素材分配表逐节落位
4. **摘要/关键词/结语初拟**：随框架同步生成防跑偏（终定在 C11）
5. 产出：框架包 C4-xxx

**守门⑥**：概念预算 ≤3 + RQ 链闭合 + 开头↔结尾镜像对称 + 结构完整性 → 放行。

## C6 正式撰写（语言环节 · 分析驱动）

> **撰写顺序**（按论证重要性）：1. 理论框架 → 2. 核心章（现象→机制→意义）→ 3. 引言（正文写完后写，对照期刊画像引言区校准）→ 4. 结论与讨论 → 5. 摘要回填。

**文风底线**（写入时即带着）：
- 段落首句：判断句开段（禁用“本文”“笔者”）
- 段落结构：三段式——判断(1-2句)→机制展开(3-5句)→边界过渡(1-2句)
- 句长：主句嵌套 2-4 层从句链；转折每 300-500 字至少 1 次
- 破折号每 500 字 ≤1 个
- 禁用：综上所述/总而言之/简单并列超过3点/毋庸置疑/颠覆性/深刻地
- **作者姿态（v12.6.1 · anti-defensive 蒸馏）**：直接推进主张——说“本文论证什么、证据显示什么”，不要默认解释“本文不主张什么、不证明什么”；写作者是向读者解释论证的作者，不是与想象中的批评者谈判的作者。**删除项**：不必要的免责声明、反复声明“本文不主张”、自我削弱贡献陈述、防御性“不是X而是Y”（与 L2 反模式联动）、为防止假想误解的过度解释。**保留项**：影响 claim 有效性/证据解读/适用范围的必要限定，集中放 methods/discussion/limitations，不散布在摘要/引言/主题句/结论。**转正改写**：“本文不声称代表所有情境”→“本文聚焦 2015-2023 城市治理案例”；“证据表明 X 影响 Y”优于“这可能表明 X 可能潜在影响 Y”。段落按方法卡11 五步推进（主题句判断→证据→warrant→回扣→过渡）。

**每节强制操作**：回顾该节论证链功能 → 按文风底线撰写（**只动语言不动论点**，内容问题登记回退 C5）→ 边界过渡句 → 更新写作状态摘要。

**写入时检查（P10 · 2026-10-10 前移优化）**：**每写完一节即扫**——禁词／半角引号／直角引号／破折号密度／“不是…而是”计数；把 C7 净化的职责**前移为“边写边检”**，C7 只做终检。理由：三轮修改实测中，半角引号（单次落 318 处）、破折号超标**均为事后脚本扫描才发现**——事后修复成本远高于写入时。

**守门⑧**：六维达标（评分维度库现行口径，锚点 ≥7 放行线）、正文区间 ±10%、style-rules 自查逐项留痕 → 放行。

## C9 初稿联合评审（v12.1 · 五席评审小组，升格既有引擎 academic-paper-reviewer）

> 本节为速查版；协议全文以 SKILL.md C9 条款为准（七智能体编制、六模式、评分聚合、回退矩阵）。

**流程**：Field Analyst 前置识别领域并配置评审人设（学术档人设：科研人员）→ 五席独立评审 → Editorial Synthesizer 收口。

| 席位 | 审什么 | 对应旧三角色 |
|---|---|---|
| EIC | 期刊适配 / 新颖性 / 重要性 | 表达评审（部分） |
| 方法学 | 论证设计 / 可复现性 | 逻辑评审（部分） |
| 领域 | 文献覆盖 / 理论框架＋增补项①理论沿用/修订双模式判定 ②案例声称vs论证区分 | 证据评审 |
| 跨视角 | 跨学科性 / 实践影响 | —（新增） |
| Devil's Advocate | 8 维论点挑战、构建最强反驳 | 攻击点清单来源 |

**质疑席自审四问＋评审输出语言规范（v12.6.1 · PMC Don't be reviewer 2 蒸馏）**：
- **质疑席自审四问**：① 这条 claim 的反例/例外是什么，作者承认了吗？② 若我是 Reviewer 2 会攻击哪段——攻击点是 booster 过强还是缺 qualifier 过弱？③ 是否区分“写作阶段可修”与“设计阶段致命”？④ 我的评审意见本身用了 hedge 还是 booster（意见非真理）？
- **评审输出语言规范**：task-not-person（批评指向论文不指向作者）；意见具体可行动（specific＋actionable）；严重度用修饰词密度传达而非情绪词；区分可修 vs 致命；评审意见自身须 hedge（“I struggle to see…”标明意见非真理），禁 booster 式断言（“This is simply wrong”）。P0-CR 裁决“严重度”判定参照评审意见 hedge/boost 比例。

**审稿立场三件套（v12.6.1 · strict-reviewer-skill 蒸馏 · MIT，2★）**：
- **问题可修性四分类**（每条问题先做致命性检验——“作者不改，结论还成立吗？”）：**A 本篇可修**（补分析/改论证/修表达 → 给具体修改路径，问题主体）；**B 不可修但必须披露**（设计/数据已定型，如横截面谈因果 → 写 Limitations＋收缩结论强度，不许要求重做研究）；**C 致命且不可修**（贡献已被做过/数据撑不起任何版本 → 直接 Reject＋转投建议，不假装“修改后可接受”）；**D 超本篇范围**（审稿人想看的扩展 → 只作建议，不参与定档，克制强加议程）。**定档只看 A/B/C**：存在 C → Reject；无 C 但 A 有硬伤级 → Major；仅轻量 A＋常规 B 披露 → Minor。与评分聚合 0-100 映射联动，作裁决表级别修正的严重度判定参照。
- **对抗性自查**：出报告前扮演“作者辩护人”逐条反驳自己写下的每条批评，**被驳倒的批评不进报告**（防虚报、防把个人偏好当硬伤）。
- **双模型互审**（双引擎可用时）：星躔五席一遍＋外部引擎（GPT/其他评审 skill）一遍——**交集＝高置信硬伤（优先改），并集＝待查清单**；两家失败模式互补（一个漏报、一个虚报）。
- **反幻觉检索核查（评审侧）**：凡评审断言“本文引用的文献不存在/前后矛盾”，必须先经检索核实（Semantic Scholar/OpenAlex/PubMed），给出可核对出处；查不到写“未能核实”，不得写入报告正文。

- **分档**：首评与投前终评走 full；中间修改轮只跑 quick 或 re-review
- **收口产出**：Editorial Decision＋Revision Roadmap；评分聚合 0-100 映射决策（≥80 放行／65-79 小修／50-64 回退矩阵／<50 结构性诊断）；SPLIT 与 DA-CRITICAL 必须呈用户裁决
- **双阈值闸（P7 · 2026-10-10 补）**：形式阈值（百分制）**＋ 席位一致性阈值**双闸——**任一席位判定“未达送外审水位”即不得放行**，须列明剩余项并进入下一轮。防“均值过线而席位判未达线”时无规则可依（实测：均值 63.7 过 60 线，两席明判未达水位）。
- **降调—补证判据（R-04 · 2026-10-10 补）**：涉**因果主张**的降调，必须同时提交可执行检验设计（测量方案／操作定义／失败信号），否则**不得以“已降调”结案**；纯表述降调（时态、强度词）方可单独放行。权威源见 `rule-base.md` §九。
- 综合决策按 SKILL.md 回退矩阵判定回退目标。验证铁律：未运行本工序不得声称“审稿通过”。
**守门⑪**：P1 致命项清零 → 放行。
