# C1 衔接协议（C1 内部节点衔接 · 权威运行协议）

> **状态**：源自 2026-08-21 用户拍板定稿 v3.0；2026-08-27 星躔化清洗后入包（去旧系统名、去个人凭据、去私有研究样例）。
> **适用范围**：星躔（StellarTrack）· C 层 C1 选题工序。不适用于 C2（材料建档）／C3（综述结构）／C4（大纲）／C5+（写作打磨）。
> **性质**：C1 内部节点衔接的权威运行协议——规定执行顺序、节点职责、S 层作用、人机决策点、产物形态与 **C1→C2 交接契约**。替代临时手填。
> **与 SKILL.md 关系**：SKILL.md C1 节为骨架摘要，本协议为节点级细节；执行顺序以本协议为准（**①态势 → ②推荐 → ⑤选题确认 → ③评测 → ④打磨**）。

## 一、C1 节点拓扑（决策链）

```
① 研究态势（比较驱动分析）
      │ 多候选横向比较 + 组合交叉矩阵 + 态势判断
      │ 输出：态势数据卡（趋势/学科/期刊/机构/基金/高频词/组合交叉/态势判断）
      ▼
② 选题推荐（中枢）── 六字段模板（三级源映射）── 产出 10 候选
      │
      ▼
⑤ 选题确认（主编级定题）── 双轨预学习 + 光谱定位 + 九维审稿 ── 收敛定稿选题
      │
      ├──▶ ③ 定题评测（先测后磨为默认）──▶ ④ 标题打磨
      └──▶ ③④ 并行（可选模式）
      ▲
      └── ③ 评测结果回注 ⑤ 改选（反馈环）
```

**结构判断**：
- ① 是**比较驱动的分析层**（多候选横向比较），非单纯数据罗列；② 是唯一中枢；③④ 是并行分支。
- ⑤ = **主编级定题**（审稿人导向），不是评分导向。
- **工具操作层可并行（①→②→③④），文档产物层线性推进**（选题卡→材料→结构）。
- **②→③④ 之间必须插入 ⑤ 人机确认**：AI 提供选项与分析，用户拍板（决策权在人，不在 AI）。

## 二、三级信息源 → 六字段模板映射表

| 模板字段 | 一级源（P0 锚定卡） | 二级源（前序对话） | 三级源（态势输出） |
|---|---|---|---|
| agent（论文场景） | 档位 → 论文类型 | — | 文献类型占比校验 |
| role（身份） | 用户画像 → 角色 | 科研场景 | — |
| subject（学科） | 投向 → 一级学科 | 研究方向 | **学科分布比较表**（判断主攻学科） |
| keyWords（≤5） | 核心概念集（前 4 个） | 兴趣词 | **高频词 + 态势判断**（补足第 5 个，避免饱和词） |
| titleNum（数量） | 需求 → 数量 | — | — |
| require（推荐理由） | **主矛盾 + 类型 + 理论锚点** | 差异化定位 | **组合交叉矩阵 + 态势判断**（研究空白 + 趋势方向） |

**写入顺序（关键坑）**：先定 agent/role/subject → 再填 keyWords → **最后注入 require** → 再 handleSend。⚠️ agent 切换会触发模板重载、把 require 重置为默认模板，因此 require 必须最后写。

## 三、S 双层作用（对初始选题的完整思维链）

```
S 层（P0 锚定卡：主矛盾/类型/理论/视角/投向/表达/验证）
 ├─ 生成端：S → 六字段模板 → ② 产出 10 候选    （约束候选怎么来）
```

**双层缺一不可**：生成端管“候选从哪来”，筛选端管“初始题怎么定”。

## 四、S 筛选端加权评估体系

### 4.1 权重分配（8 维度，总分 100）

| 层级 | 维度 | 权重 | 来源 |
|---|---|---|---|
| **核心轴 45%** | 主矛盾承载度 | 25 | S 论证锚定 |
| | 类型落位度 | 20 | S 拍板 |
| **重要支撑 30%** | 理论锚定度 | 15 | S |
| | 结构支撑度 | 15 | S |
| **辅助 25%** | 学科投向度 | 10 | S |
| | 视角归属度 | 5 | S |
| | 表达兼容度 | 5 | S |
| | 验证通过度 | 5 | S |

### 4.2 评分与收敛规则

1. 每维度打 1-5 分（5=完全命中 S）。
2. 加权总分 = Σ(维度分 × 权重)，满分 500。
3. 按总分排序候选 → 收敛初始选题；AI 提供矩阵与解读，**用户最终拍板**。
4. **权重可配置**：默认按主轴；若 P0 变量/模式改变可调（如偏实证论文提高“验证通过度”）。

## 五、⑤ 选题确认节点（主编级定题 · 审稿人导向）

> **核心原则**：审稿人导向（非评分导向、非自由导向）。主编一眼判断：这题目行不行、能不能投、怎么改。
> **优先级链**：**主编评估 > S 加权**（外部标准优先于内部标准——论文最终要发表，不是要贴 S）。

### 5.1 两级定题机制

#### 第一级：10 → ≤4（用户导向粗筛 + S 加权辅助）
- 依据：**用户喜好 + S 加权排序 + 主编快筛**（三重输入）
- 输出：最优推荐 **≤4 个**候选（每个附一句推荐理由），其中 **≤3 个**进入第二级
- 目的：减负，把 10 压到 3 个以内进入深评估；不复杂评估、不评分

#### 第二级：≤3 → 1（主编级定题 · title-assessor）

调用 `title-assessor` skill（双轨预学习版），执行：

```
轨道 A：加载通用语料库（主编审题经验 / 期刊选题偏好 / 正反案例）
轨道 B：目标刊动态预学习（每次必做）
    B.1 主编经验搜索（该刊主编访谈）
    B.2 最新目录分析（最新 2-3 期，五维规律）
    B.3 生成期刊会话档案
    B.4 视角切换（以目标刊主编为准，期刊适配权重临时提升）
三步一眼判断
    看题式（名词性短语？副标题窄于主标题？）
    抠概念（5 秒可懂？自造词有谱系锚点？）
    找新意（新在哪一层？做得出吗？）
九维审稿
    问题意识 20% / 概念清晰 15% / 创新信号 15% / 概念密度 10%
    可行性暗示 10% / 题式规范 10% / 期刊适配 10% / 表达凝练 5% / 前沿承接 5%
光谱定位
    论断式 > 概念对举式 > 对象+论域式 > XX研究式 > 堆砌式
等级判定
    A 可直接投 / B 微调 / C 大改 / D 不建议
输出（八段）
    1. 目标刊预学习摘要 2. 题目拆解+光谱定位 3. 三步一眼判断
    4. 九维审稿 5. 主编视角 6. 等级判定 7. 优化建议（2-3 个改写题目）
    8. 期刊适配提示
```

### 5.2 定稿产出

**定稿选题卡** = 定稿标题 + 关键词 + 研究问题 + **竞争文献划界表** + 主编级审稿意见 + 模式选择

| 字段 | 内容 | 用途 |
|---|---|---|
| 定稿标题 | 优化后的主标题+副标题 | ③评测 + ④打磨 |
| 关键词 | 3-5 个核心概念 | ③评测输入 |
| 研究问题 | 一句话概括 | ②模板 require 字段 |
| **竞争文献划界表** | 三栏表：`最强对手`｜`其已占位`｜`本文增量`（逐行须落到对象／机制／层次之一） | 判新增量是否真实；C2 材料门与 C3 综述门的上游锚 |
| 主编级审稿意见 | 等级判定 + 优化方向 + 期刊适配 | ④打磨参考 |
| 模式选择 | 先测后磨 / 并行 | ③④执行模式 |

#### 5.2.1 竞争文献划界表 · 填写纪律（2026-10-10 补 · 清单第六节正向做法第 5 项转正）

**为什么立此表**：③ 评测回答的是“能不能做”（发文量／竞争度／期刊匹配），却**不回答“新在哪”**；而主编一眼判断的第一问恰是“新意在哪一层”。此表把“新意”从印象变成**可核对的格子**。

**格式**（三栏，一行一对最强对手，缺一不可）：

| 最强对手 | 其已占位 | 本文增量 |
|---|---|---|
| {作者+年+核心论断} | {对象／机制／层次 中已占的那一格} | {同上三格中本文占哪一格} |

**填写纪律**：

1. **只列最强对手**——列弱对手会把增量做虚，等于给自己发合格证；宁少勿滥，一行亦可。
2. **三格定位**：`对象`（研究谁／什么文本）｜`机制`（哪条因果或逻辑链）｜`层次`（元理论／中层／经验）。两栏须**同格对读**才有意义。
3. **划界失败判据**：若任一行的“本文增量”栏写不出**三格中任一格的具体差异**（只能是“视角不同”“更全面”这类形容词）→ 判**本题尚无增量**，退回 C1 步骤①重选，**不得进入 ③ 评测**。
4. **与既有门的先后**：本表是 `C2 材料门`（来源分级白名单）与 `C3 综述门`（命题张力三类薄弱段）的**上游锚**——**先划界，再判材料够不够、综述有无张力**；顺序颠倒会把“材料多”误当“有新意”。
5. **不另设门槛**：本表属选题卡**必填字段**（与关键词同级），但判据仍只卡守门③原有的“新颖性三维”，本表是其**证据形式**，**不新增分数、不新增守门**。

### 5.3 与 S 加权的关系

| 评估体系 | 性质 | 优先级 |
|---|---|---|
| **主编评估** | 外部标准（审稿人认不认 = 发表成功） | **优先** |
| S 加权 | 内部标准（贴不贴 S 灵魂） | 辅助 |

**冲突处理**：主编评估与 S 加权冲突时，以主编评估为准；S 加权可作为优化建议的参考。

## 七、实测技术要点

> **入口变更（2026-08-22 实测）**：`kns8s.cnki.net` 子域已下线，检索界面现挂 **`https://kns.cnki.net/kns8s/`** 下；旧协议中 kns8s 独立域名引用一律按此替换。

### 7.1 态势数据源（kns 分组浏览 + x.cnki.net 接口）

**kns 分组浏览**（主数据源）：
- 入口：`https://kns.cnki.net/kns8s/defaultresult/index?kw={关键词}`
- 分组维度：年度 / 学科 / 期刊（文献来源） / 机构 / 基金 / 主题（高频词）
- 抓取方式：有头浏览器 MCP 驱动（左侧面板 DOM）
- 优势：公开可用、无需登录、速度快、数据全

**x.cnki.net 接口**（组合交叉数据）：
- 组合发文量：`POST ix.cnki.net/topic/assempent/keyWord`（body: `{title:"",keyword:"A;B"}`）
- 组合趋势对比：`POST ix.cnki.net/topic/aiRecommend/keyWordCompares`（body: `{keyword:["A","B","A;B"]}`）
- 期刊推荐：`POST ix.cnki.net/topic/aiRecommend/journalRecommend`（body: `{keyWord:"A;B", num:5}`）
- 溯源文献：`POST ix.cnki.net/topic/aiRecommend/recommendList`（body: `{keyword:"A;B", size:100}`）
- 高频词：`POST ix.cnki.net/topic/aiRecommend/imageWord`（body: `{keyword:"A;B"}`）

**组合使用**：kns 分组浏览 = 单主题维度；x.cnki.net 接口 = 组合交叉维度；两者互补，不可替代。

### 7.1.1 接口实测勘误（2026-10-16 · 轨 B 实测记录）

> 轨 B 端到端实测（无浏览器、无登录态环境）验证结果——**以下三条原承诺需修正，否则轨 B 用户会卡在①**：

| 数据源 | 原承诺 | 实测 | 修订 |
|---|---|---|---|
| x.cnki.net aiRecommend 系列（趋势对比/期刊推荐/溯源文献） | 组合交叉数据 | **HTTP 200 但 code=5014 认证失败**——**需登录态**（用户自持知网账号） | 标注“**需登录态**”；无登录态 → 走降级分支（见 §8.6.3 轨B ①备注） |
| x.cnki.net imageWord（高频词） | 高频词 | 免登录可调但 **keyword 参数不生效**（返回兜底词表，与主题无关） | 标注“**需登录态才按主题计算**”；无登录态不作态势数据 |
| kns 分组浏览 | 公开可用无需登录 | 需**浏览器 DOM 渲染**（纯接口/文本抓取不可达） | 标注“需浏览器”；无浏览器 → 走降级分支 |

**降级分支（轨 B ①）**：无浏览器／无登录态时，用**公开检索**（通用搜索/学术搜索，能回查到刊题录即可）构建态势数据卡，产物标注“降级·源=公开检索”；证据链三锚的锚1 相应放宽为“**可回查的真实题录**”（检索源不限 kns）。

### 7.2 选题推荐（x.cnki.net 选题分析工具）

- 入口：`https://x.cnki.net/web/topic/#/topicRecommend`
- 驱动：有头浏览器 MCP（真浏览器 + 用户登录态）
- 触发生成：`InputTemplate.handleSend()`（过校验 → 真实请求链）
- 表单写入路径：`InputTemplate._data.templateConfig.fields[]`（key: agent/role/subject/keyWords/titleNum/require）
- 写入顺序：先定 agent/role/subject → 再填 keyWords → **最后注入 require** → 再 handleSend

### 7.3 定题评测 / 标题打磨（x.cnki.net 页面原生 AI 生成 ⚠️ 非接口抓取）

**③ 定题评测 / ④ 标题打磨是知网选题分析页面的原生 AI 生成功能，必须驱动真浏览器跑页面，不能用接口数据替代、不能人工拼装。**

- ③ 定题评测入口：`https://x.cnki.net/web/topic/#/topicEvaluation/?model=tencent_origin_deepseek_v4_pro_think`
- ④ 标题打磨入口：`https://x.cnki.net/web/topic/#/titlePolishing/?model=tencent_origin_deepseek_v4_pro_think`
- 表单通用字段：role（角色）/ subject（一级学科，如艺术学=13）/ paperType（论文类型）/ direction（定稿标题）/ titleNum（方案数量，默认 5）
- 触发：`InputTempalte.handleSend()`（按钮 click 可能无效，直接调组件方法）
- 产出：③ = 8 维度星级评估（综合评价/可行性/创新性/跨学科整合性/背景与意义/应用价值/重要性/风险与挑战）+ 相关文献数 + 期刊推荐；④ = N 个差异化标题方案（中英双语+拆解+学科适配+优化论证）+ 差异化策略总结

**数据层写入要点（实测逆向 handleSend 拼装链）**：
- 定位：`#app.__vue__` 组件树递归找含 `direction` 字段的 `InputTempalte` 组件
- 字段配方：role=`{roleName:'...'}`；subject=`value=['学科代码']` 数组 + `valueCn=[['学科名']]` 嵌套数组；paperType/direction/titleNum 为字符串
- **发送前零成本预检**：调 `target.transformFieldsToInfo()` 检查返回 `content` 含目标学科字段，通过才 handleSend，不浪费额度
- 等待：SSE 流式输出约 2-4 分钟，轮询 `sendLoading`/`正在评测`/`思考中` 状态

### 7.4 登录态维护

- token 存 `localStorage.X_JWT_LIST`；导航/刷新后可能丢失，需重登
- **凭据不入册**（按《外部接口登记册》纪律）：账号密码由用户自行保管，本协议不记录、不传播；AI 只引导用户登录
- 重登后自动恢复选题分析会话
- kns 分组浏览无需登录（公开可用）

## 八、推进纪律

> **核心原则**：C1 工序顺序已实证确定（①→②→⑤→③→④），按线性推进，不每步征询“要不要继续”。

1. **线性执行**：每完成一步，直接肯定告知“下一步固定动作是 X”，不发出“是否现在执行 X？”的询问式结尾。
2. **用户可中途讨论**：讨论/纠偏不改变主线顺序，仅在当前节点细化；主线（①→②→⑤→③→④）不变。
3. **关键拍板点仍以用户为准**：⑤主编级定题的“选哪个/怎么融”是用户决策，但“执行 ⑤第二级”这个动作本身是固定的，直接做、做完呈现，不先问。
4. **措辞纪律**：结尾禁用“建议”“是否”“要不要”，改用“下一步固定动作是 X，我现在执行/已执行”。

## 八·五、产物资产化与 C1→C2 交接契约

> **背景**：写作情境中大量内容需反复思考与复用，一次性报告式产物造成重复劳动。C1 第一层文献综述结果（kns 分组 + ②③④参考来源）必须正式衔接 C2 第二层（深度检索与建档）。

### 8.5.1 资产化三原则

1. **产物双写**：每道工序产出 = 可读报告（人审用）+ 资产登记条目（机引用，带 asset_id）。
2. **ID 引用制**：下游工序引用 asset_id 取用，不重复思考、不重新拼装。
3. **入池必补全**：知网参考来源只有[序号]无题录，必须经 kns 回查补全题录后才算入池。

| 类型 | 内容 | 来源工序 | 消费方 |
|---|---|---|---|
| **A-LIT 文献池** | 去重合并的题录集 {asset_id, 题录, 来源工序, 主题桶, 用途标签} | ②+③+④+kns 分组 | C2 建档种子 / C4 引文 |

### 8.5.3 C1 第一层 → C2 第二层 交接契约

- C1 第一层（kns 分组浏览 + 选题工具参考来源）= **粗文献池 + 检索先验**，不是终态。
- C2 第二层（cnki 深度检索 + 建档）**以 A-LIT 为种子扩展**，不从零检索；扩展结果回写 A-LIT。
- **交接五件套**：C1 总成卡（权威口径）+ A-LIT 索引 + 定向补证清单（③风险项）+ 检索式（主/扩展）+ 概念卡。

## 八·七、选题两阶段化：问题定稿后置（v12.6.3 · 方法论背书）

> **背景（2026-10-16 检索验证）**：研究问题开发是**迭代过程**（working→finalized），文献综述是修正问题的最佳窗口（Manuel Garcia / PMC / 巴塞尔大学 / 风笑天 / 清华两阶段文献调研均支持“初步问题→综述→定稿”）；纯缺口匹配（gap-spotting）产出平庸选题，须补**假设挑战**（problematization，Alvesson & Sandberg 2011）提升先锋性。
> **核心变更**：C1 的“定稿”动作**整体后移到 C3 综述收尾**——C1 只做“方向预选”产出**初步问题卡（PRQ）**；综述后经**“缺口匹配×假设挑战”双检查**再定稿。**本节覆盖 §一 原执行顺序的定稿语义**（①→②→③′方向预选→综述→④′问题定稿）。
> **补充发现**：①论文呈现顺序（洋八股：问题在前）≠ 研究实际过程（迭代）——成稿引言按“问题先行”呈现，研究过程按本节点推进，两层分开表述；②综述型研究（系统综述/文献计量）走相反规则——问题**先验注册**（PRISMA 逻辑），见 §8.7.7。

### 8.7.1 三阶段五节点拓扑

```
阶段一（C1 · 方向预选）          阶段二（C2/C3 · 综述校准）          阶段三（C3 收尾 · 问题定稿）
① 态势                            C2 建档（基于 PRQ 关键词）          ④′ a 缺口匹配检查（三态）
② 推荐（生成工具箱）               C3 泛调研→精调研                   b 假设挑战检查（四步·人机分工）
③′ 方向预选（PRQ 卡）              Gap 卡产出                         c 再推敲（P2/P3/P4＋九维）
守门③′：方向已选＋题录回显          问题锚冻结＋漂移日志                 d Q-Log 变更留痕
                                                                     用户拍板 → 守门③″ → 放行 C4
产物：PRQ 卡（初步）              产物：Gap 卡                       产物：定稿选题卡＋论文题目
```

**与 §一 原拓扑的差异**：原 ⑤（选题确认·定稿）拆两半——“方向预选”留在 C1（③′），“定稿”后移到 C3 收尾（④′）；原 ③（定题评测）的三维＋外部撞车后移到 ④′c；原 ④（标题打磨）留在定稿后。

### 8.7.2 初步问题卡（PRQ · C1 产出）

> 定位：**不是定稿**，是“带方向的研究假设”——只装综述前能确定的，把“要文献才能确定的”全部列为待综述验证项。综述完成前禁止升格定稿。

```markdown
## 初步问题卡（PRQ）｜编号 C1-PRQ-xxx
**状态**：〔初步·待综述〕
一、现实锚（来自 O2 定稿契约＋经验观察）：现实现象/张力一句｜谁受影响/影响在哪｜为何现在值得关注
二、初步研究问题：初步问题表述（可粗）｜初步判断句（假设方向）
三、待综述验证项（本卡核心 · 综述后逐项回答）：
  ① 缺口假设：我猜这里没人做/没做透 → Gap 卡对照
  ② 竞争者：疑似已有同类研究 → 划界表定位
  ③ 可行性假设：数据/材料可达 → P2 五维复核
  ④ 方法意向：拟用方法适配 → P3 预锁
  ⑤ 边界假设：对象/范围成立 → P4 四问
  ⑥ 假设挑战候选（可选）：预猜领域内可被挑战的隐含假设
四、检索接口（守门③′判据）：关键词 3-5 个（可进 kns/公开库实测）｜题录回显 1-3 条（可回查真实题录，缺则回 ② 换方向）
五、方法意向（可空）：拟走方法轨（理论/实证量化/实证质化/混合）
六、决策留痕：轨别（A/B＋权益依据）｜方向来源（矩阵格/悖论/三轮收敛/续写既有稿）｜预选理由一句｜与论文体系关系
```

**入口 A/B 差异**：入口 A（从零）待验证项全五项；入口 B（成稿/续写进系统）PRQ 直接从半成稿提取判断句，待验证项聚焦“缺口匹配”（检验已写题是否真符合缺口），其余项按需。

### 8.7.3 守门③′（C1 出口 · 可进综述判据）

**方向已选（用户对候选方向明确选择）＋ 3-5 关键词可检索 ＋ 题录回显 1-3 条真实题录**（轨 B：检索源不限 kns，公开检索可回查即可；轨 A：研学智得检索）——三者齐备放行 C2。无题录回显 → 回 ② 换方向，不得带着“无文献支撑的方向”进综述。

### 8.7.4 双检查（C3 收尾 · 问题定稿环节）

**检查 a：缺口匹配（三态判据）**

```
PRQ 初步判断句 × Gap 卡（C3 产出）
├─ 匹配      → 进入检查 b（聚焦收敛：对象/边界/机制or形态/验证口径四问）
├─ 部分匹配   → 收窄或平移问题表述，回 C2 补一轮精检索后重入
└─ 不匹配    → 回 C1 ② 换方向（PRQ 作废留档；文献池关键词迭代复用不浪费）
```

判定依据五类 Gap（方法卡18 §二：文献/方法/应用/跨学科/时间），逐类标注 PRQ 命中的是哪类。**缺口卡编号规范（v12.6.3 补）**：每条缺口登记为 **Gap-NN**，检查结论、Q-Log 触发源、C2 补证清单用编号引用（如“命中 Gap-01 文献缺口”），不用描述指代——保证跨环节可回查。

**检查 b：假设挑战（problematization 四步 · 人机分工）**

> 目的：防“符合现实却纯填空缺”的平庸选题，把先锋性显式化。蒸馏 Alvesson & Sandberg 六步为四步（Organization 2011；AMR 2011）。

| 步 | 动作 | 输出 | 责任人 |
|---|---|---|---|
| 1. 识别假设 | 在 Gap 卡涉及的代表文献中找 1-2 个被默认接受的前提（五类：学派内部/根隐喻/范式/意识形态/场域共识） | 假设清单 | AI |
| 2. 检验可挑战性 | 该假设是否已被挑战？是否有历史变迁/矛盾证据/替代视角？ | 可挑战性判断 | AI |
| 3. 提出替代 | 反转/扩展/整合，形成替代性前提 | 替代假设一句 | AI |
| 4. 有趣性评估 | 三档判据：太 obvious（无聊）／太 absurd（没人信）／恰在中间（This is interesting!） | **先锋性判定** | **用户** |

**裁决规则**：①过不了检查 a → 不进检查 b；②检查 b 通过 → 标注“**挑战型选题**”；③不通过（纯缺口型）→ 标注“**缺口型选题**”（缺口型可发表，只是先锋性弱；可回 C1 ② 升级也可接受现状）。

**检查 c：再推敲（定稿前最后一道）**——P2 可行性五维复核（综述后数据可达性更清）→ P3 方法轨预锁确认 → P4 聚焦四问＋可证伪性（方法卡18）→ title-assessor 九维审稿（沿用原⑤判据）→ **用户拍板** → 标题打磨（理论前缀＋冒号＋研究对象）。

### 8.7.5 守门③″（定稿出口 · 可进 C4 判据）

**双检查通过（缺口匹配非“不匹配”态＋假设挑战有明确判定）＋ 用户已拍板标题 ＋ 标题打磨记录留痕**——三者齐备放行 C4；否则选题卡状态保持“草稿（挂起）”（与守门②挂起态对齐）。原守门③ 的“三维评测达标”语义由检查 a（缺口）＋检查 c（P2/P3/P4＋九维）承接。

**挂起即停笔（v12.6.3 实测驱动 · 契约 6 落地）**：选题卡处于“草稿（挂起）”时，模型**必须停笔呈报**——输出候选题＋推荐答案＋待拍板项清单，等待用户回复；**禁止带着挂起继续写综述正文或进 C4**（挂起是停笔信号，不是可绕行状态标记）。同理，守门③′（方向确认）、④′b（有趣性裁决）、④′c（标题拍板）均为**硬停顿点**：模型产出产物＋呈报待确认项后停笔，收到用户原话确认才推进；不得自问自答代办“用户已选择／已拍板”。

### 8.7.6 Q-Log 问题演进记录（定稿选题卡必附）

```
## 问题演进记录（Q-Log）
| 版本 | 阶段 | 问题表述 | 触发源（文献/现实/用户·引用 Gap 卡编号） | 变更性质（原则性/漂移） | 裁决 |
| PRQ | C1 | …… | —— | —— | 方向预选 |
| RQ v1 | C3 综述后 | …… | 文献 X 显示缺口在 Y 而非 Z（Gap-02） | 原则性 | 修订 |
| 定稿 | C3 收尾 | …… | 双检查通过 | —— | 拍板 |
```

Q-Log 三用途：①成稿引言解释“为什么最终问题是对的”（回写依据）；②审稿答辩证据链；③E 层复盘输入（问题演进即研究过程资产）。
**综述期纪律**：PRQ 初步判断句作为**问题锚**贯穿综述期，修订必须有文献理由（principled refinement）；无理由漂移（arbitrary drift）记入 Q-Log 并标注，连续无理由漂移 → 触发回退上限（见 §8.7.7）。

### 8.7.7 纪律与适配

1. **回退循环上限**：缺口“不匹配”回 C1 换方向设**两轮上限**；两轮仍不匹配 → 触发 W4 选题矛盾裁决（以最高层级锚定物收束：已写摘要＞存量理论模型＞对话最新表述）或降级为局部维度。
2. **档位/深度适配**：**学术档全流程**（双检查）；**快速档**（学位论文/普刊，可简化为单检查=缺口匹配即可，跳假设挑战须声明“快速档·单检查”）；**非学术档**（传播/创作）不启用两阶段，PRQ 退化为普通选题卡。
3. **综述型研究分支**（选题本身是系统综述/文献计量类）：规则相反——研究问题**先验注册**（formulated before formal search）、检索协议锁定、不随证据变更（PRISMA 逻辑）；PRQ 直接升格为协议卡。
4. **S 层接口**：S 加权拆两段——PRQ 时初步 S 加权（粗判，S 生成端照旧约束候选），定稿环节复评（细判）；判断句以定稿版为准，S2/S3 重锚以定稿判断句为对象。
5. **三库归属**：生成工具箱/双检查表→**M 库方法卡**（方法卡05/17/18）；PRQ→RQ→Q-Log 演进→**K 库知识资产**（跨论文复用）；Q-Log 复盘→**E 库沉淀输入**。
6. **人机分工铁律**（同 §8.7.4）：AI 出选项与分析（假设清单/可挑战性/替代假设），**用户裁决**（有趣性三档/拍板）——决策权在人。**停笔等待（v12.6.3 补）**：AI 呈报后必须停笔等用户原话裁决，禁止在同一回复内自我代办拍板；无用户原话的守门判据（“用户已拍板/明确选择/裁决”）一律视为未过。
7. **卡间字段映射**：PRQ 待验证项①缺口→Gap 卡五类 Gap；②竞争者→竞争文献划界表（§5.2.1）；③可行性→P2 五维；④方法→P3 预锁；⑤边界→P4 四问；⑥假设→检查 b 假设清单。Q-Log 触发源引用 Gap 卡编号。
