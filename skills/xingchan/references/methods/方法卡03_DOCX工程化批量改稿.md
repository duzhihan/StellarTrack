# 方法卡03 · DOCX 工程化批量改稿流水线

> **适用档位**：回溯档（结题/调研报告）、学术档（论文终稿）、规范档（长篇公文）
> **适用工序**：C10 改论文 · C11 最终精校（多轮评审后的系统性批量改稿）
> **来源**：广西哲社 某省社科课题 结项报告改稿工程（批1–批17，2026-09-13 完链）·【实战】
> **一句话**：把“手改文档”升级为“可审计、可回滚、可复测”的工程化流水线——改稿不是编辑动作，是受护栏约束的落改作业。

---

## 一、五条铁律（总原则）

1. **通道唯一**——一切落改走 `zipfile` 直改 `word/document.xml`，**禁用本地编辑器通道**（会丢嵌入字体 `fonts/*.odttf`、`customXml/`、`docProps/custom.xml`，并改动段落数与样式计数）。
2. **批次化**——一批一脚本、一备份、一对照件、一 md5。**批次粒度＝单一改稿意图**（如“批12 结构收束”只做结构，不掺表达）。
3. **护栏先行**——所有断言在**写回前**触发，宁可零坏盘也不写出坏文件。
4. **交付只出 md**——对照件一律 markdown；母本不覆盖，除非用户明确授权＋先备份＋事后核验 md5/段数/部件数。
5. **不着色原则**——改稿不加红标，以免覆盖作者自用蓝标；可查性由“段号＋改前/改后”对照件承担。

---

## 二、七道护栏（每批必跑）

| # | 护栏 | 断言 | 治什么 |
|---|---|---|---|
| G1 | 基线校验 | 起手 `md5(DOC)` == 预期值 | 防改错版本 |
| G2 | 定位唯一 | 目标串全文命中 `== 1` | 防误改他处 |
| G3 | **段文本＝预期串** | 改写后段文本 `== old[:o]+new+old[oe:]` | **防 run 双装／结构事故（本卡最关键）** |
| G4 | 删段连带脚注 | 引用 id 集合 ⊆ 条目 id 集合、悬空 0、条目数与引用数同步递减 | 防 `footnotes.xml` 孤儿条目 |
| G5 | 结构不变量 | 段数／引用数／表数／部件数 按预期增减 | 防隐性结构损坏 |
| G6 | 13 字滑窗 | 改写串不制造新重复窗（法规名豁免） | 防“降重”变“增重” |
| G7 | 违禁串 | 违禁词表全 0 | 防术语回潮 |

## 三、关键坑位（实战教训·血泪版）

1. **run 双装**（最凶）——`para_edit` 的 `parts` 若含 before-runs、而 `p[:runs[wi].start()]` 前缀又天然包含它们 → **文字成对重复**（“句子句子”）。修法：`parts = [前段文本] + [新文本] + [后段文本]`，并必加 G3 断言当场拦截。曾两次复发、两次被断言拦下。
2. **段号口径（2026-09-13 批18 复现·机理细化）**——段落正则的**两个分支顺序不可颠倒**，否则段号整体错位：
   - ✓ 正确：`<w:p\b[^>]*/>|<w:p\b[^>]*>.*?</w:p>`（**自闭合分支在前**）→ 本报告 1793 段，`<w:p/>` 单列
   - ✗ 错误：`<w:p\b[^>]*>.*?</w:p>|<w:p\b[^>]*/>`（自闭合在后 → **该分支永不命中**）→ 1792 段
   - **机理**：`<w:p\b[^>]*>` 中的 `[^>]*` 会吸收 `/`，故 `<w:p/>` 能被“第一分支的开头”吃掉，再由 `.*?</w:p>` 吞并到下一个真正的段尾——**两段并作一段，其后段号整体前移**。本报告自闭合段位于索引 3、7（极靠前），一次事故即致全篇段号 −1，与批1–批17 全部记录错位（症状：审阅报告说“段860”、自查却在 859）。
   - **处置**：口径固定为“自闭合在前”；且**不凭序号直取**——一律以“期望串全文唯一命中”定位（G2），序号只作日志与人读锚点。复用旧批次脚本时，**先核其基线段数是否与现稿一致**再动手。
3. **注号非文字**——文档里的“〔注N〕”**不是文字**，是 `<w:footnoteReference>` 在文本抽取层的呈现；判“某段有无注号”必须走 XML（原始 XML 中字符串`〔注`出现 0 次）。
4. **删段必清脚注**——删段落前先采集该段 `<w:footnoteReference>` 的 id，随段一并清理 `word/footnotes.xml` 对应条目（G4）。未加护栏会留下孤儿条目（实战曾一次险些留 14 条）。
5. **写回双通道**——`os.replace` 失败（文件被占用）→ 转 `shutil.copy2`。**占用者不止 WINWORD.EXE，WPS 文字同样占用，预览面板亦占用**；锁是间歇的，故写回链一律“replace → copy2”双通道。
6. **zip 重打包按 `infolist()` 逐项 `writestr`**——写成 `namelist()` 会**丢弃 zip 目录项**（部件数莫名变少、Word 签名异常）。
7. **半角双引号陷阱**——XML 中 `"` 写作 `&quot;`（6 字符），转全角后 1 字符，**文件“字符数”统计会降 5×n，非内容丢失**。
8. **反引号陷阱**——`python -c "…"` 双引号内的反引号会被 bash 当命令替换而静默清空；**凡写入含反引号的文本，一律 Write 成 .py 脚本再执行**。
9. **内联脚本输出截断**——用 `| head -N` 核对清单会致尾部条目“消失”造成虚惊；完整性核对须 `tail` 或分段取。
10. **PowerShell 中文路径不可靠**——`New-Item`/`Copy-Item` 目标含中文时静默失败；**凡涉及中文路径的增删改，一律 Write .py 用 Python 执行**，并回查尺寸与 md5 判成功。
11. **改标题＝改两处：正文标题 ＋ 目录条目（2026-09-13 批19 实战）**——目录条目是 **TOC 域结构**（`HYPERLINK \l _TocXXXX` ＋ `PAGEREF` 域），但其中的标题文本是**独立 run**，可安全定点替换：
    - **唯一锚的建立**：同一标题串在正文与目录各出现一次，两个 run 的 XML 可能**逐字节相同**，无法直接区分。用**相邻元素**破平——目录 run 后随 `<w:tab/>`（制表位接页码），正文标题 run 则前置/后随 `<w:bookmarkStart w:name="_TocXXXX"/>`。取“后随 `<w:tab/>`”或“前置 bookmarkStart”作锚即可各锁一处。
    - **只改 `<w:t>`，绝不动 `<w:instrText>`**——`instrText` 是域开关参数（HYPERLINK/PAGEREF 的 `\l`/`\h`），一改域即失效。
    - **双保险逻辑**：正文标题已改的前提下，即便不刷目录，TOC 缓存文本也一致；刷目录（Ctrl+A→F9）时再由域重算页序。
    - **顺带修订**：只改章题时，须核该章“节题层”是否仍保留原节略词（如节题“双向调适与认同重塑”应保留，只有升格为章题才须与机制名对齐）。
12. **插入段落与节序顺延（2026-09-13 批21 实战）**——在附录／章节中**新增小节**牵动面远大于“替换”，是一次小型结构手术：
    - **插入原语** `insert_after(xml, anchor_idx, new_paras)`：取锚段完整 XML、`assert xml.count(p)==1` 唯一化、`xml.replace(p, p+new_paras, 1)`。锚段选**新内容应紧随其后的那段**（如“二、”节末段），**不是节标题段**（否则插到标题之前）。
    - **有歧义段号须强制索引**：节标题串（如“三、情绪与评价词典”）在**目录条目与正文标题各出现一次**，纯文本定位必命中 2 处而中断。修法＝给 `run_replace` 增 `want_idx`（1-based 强指段号）并断言该段含目标串；目录侧与正文侧各调一次、各给显式段号。
    - **节号顺延须双写**：插入“三、”→ 原“三/四/五”的**正文标题与目录条目各顺延一位**（实战：3 处正文＋3 处目录＋1 条新目录）。顺延串同样有歧义（正文/目录各一），一律 `want_idx`。
    - **执行顺序＝段号降序、插入置其区域最后**：凡基于段号的定位须**从大到小**执行；插入动作放在其所在区域的**最后一步**，避免先前插入的位移污染后续段号。对照件须给“段号位移表”。
    - **新目录条目构造**：复制一个**同类现有条目**的完整 XML（含 `HYPERLINK \l` ＋ `PAGEREF` 域结构），改 `paraId`（新值）、`_TocXXXX`（→新书签名；**HYPERLINK 与 PAGEREF 两处都要改**）、`<w:t>` 文本；页码沿用相邻值即可（F9 会重算，不手工搬）。
    - **新书签／id／paraId 防冲突**：新书签名（如 `_Toc90210`）与 paraId 落改前断言全文未占用；bookmark id 取 `max(现有 id)+1`。
    - **终检断言走纯文本层**：`run_replace` 重建的 run 写成 `<w:t xml:space="preserve">`，故**不可用 `<w:t>文本</w:t>` 匹配新值**（会漏）——改在 ptext 拼接层计数。
    - **结构不变量按预期增减**：插入 N 段则断言 `段数 == 基线+N`（引用数／表数／部件数不变）；并加“旧名归零”消歧断言（旧节名出现次数 == 0）。
    - **别轻信“不入目录”的旧判断**：附录/后置章节的节标题**仍可能列于目录**（style 已降级为空、但 `_Toc` 书签残留 → 目录条目未随之消失）。改节名前**先探目录区**，否则节名与正文不符。

## 四、评审制（多轮专家审）

- **五席联审 ＋ 对辩席**；加权示例 `.25/.20/.15/.20/.20`。
- **分级**：Critical ／ Major ／ Minor。产出《联合评审报告》＋《意见处置总表》。
- **闭环**：处置总表 → 批次规划 → 落改 → 复测 → 复审；**分数应单调上升**。
- 实战轨迹：C9 74.6 → C13 81.2 → C14 82.4 → C15 86.6（Minor Revision，无 Critical、无 Major）。
- 复审须**逐条机器核验**上轮意见是否落地（非印象判读）。

## 七、经验提炼（可迁移的习惯）

1. **判断先行**——改稿的第一动作是诊断（探针脚本出数据），不是动手；先出诊断报告，再定方案，后做对照。
2. **无数据不造数**——凡阈值须来自用户指示或规范原文；无来源只“报数”，不“设限”。
3. **先定方案，后做对照**——方案级内容一律独立落盘 md（对话会被折叠）。
4. **断言即文档**——护栏脚本本身就是经验的可执行化；每踩一个坑，就把断言加进模板。
5. **防空转**——凡要写新脚本／新文件，最多 Read 既有文件 2 次作参考，第 3 次前必须 Write 落盘。
