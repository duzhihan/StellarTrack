# 标尺稿背靠背评分任务书（B 项校准 · 用户侧）

> 目的：与 agent 评审轨背靠背打分，检验六维锚点表是否**双方共用同一参照系**
> （评分维度库 §五 第四层校准 · 第 4／7／11 条）。
> 铁律：未校准的尺子量不出长度——**锚点表经本任务验证前，C2 硬门仅作提示性检查，不强制阻断**。
> MarxSphere 教训：**kappa=1.0 比 0.6 更该警惕**（样本无梯度假性完美）——请务必独立判档，勿对齐 agent 分。

## 一、两面板分工（v12.5.8 · 校准协议第 11 条）

| 面板 | 样本 | 用途 | 是否作放行判据 |
|---|---|---|---|
| **blind** 盲评面板 | 六篇（S1–S6） | 测“用户与 agent 是否共用同一把尺” | **是——唯一来源** |
| **real** 真实稿面板 | 四篇（R1–R4） | 测“尺子的外部效度”（双方序 vs 刊物层级锚） | **否——只作诊断** |

**real 面板为何不作判据**：① 您知各稿刊物层级，存在**锚定污染**（按层级反推分数→虚假对齐）；
② 真实稿的效标在刊物层级那一侧，不在“双方一致性”这一侧；③ 外部锚本身是粗代理
（实测同层级内部两稿分差达 2.00 分）。故 real 面板恒不参与放行判定。

## 二、操作步骤（两条通道，任选）

1. 打开对应页面（预置在会话中；如需重新生成：
   `python data/build_calibration_rater.py`（盲评）／`python data/build_real_rater.py`（真实稿））。
2. 逐篇逐维点选档位（每维五档：1／3／5／7／9）。点选后页面即时显示该档锚点定义，可据此复核。
3. 评满后，页面底部**常驻显示紧凑码**，形如：

   ```text
   S1: 1 1 1 1 1 1
   S2: 3 3 3 3 3 3
   ```

   顺序＝内容质量／逻辑严密性／证据可回指性／规范合规性／可读性／适配度。
4. **把紧凑码原样贴回对话即可**——不必点“导出 JSON”。

> **通道铁律**：内嵌预览环境里 `Blob`／`a[download]` 下载**不落盘**（已多次实测），
> 剪贴板亦可能被拦截。故**紧凑码常驻显示＋手工复制**是唯一可靠通路，
> “导出 JSON 文件”仅作备用，**不得作为唯一通路**。

## 三、六维锚点摘要（完整表见 `references/评分维度库.md` §二）

打分前先**定位档位**再微调，不允许跨档。7 分＝放行线。

- **内容质量（30%）**：1 实质物缺失仅形式／3 空泛套话／5 成立但停中位无判断／7 实质成立判断显式可依／9 同 7 且第二席复评同档
- **逻辑严密性（20%）**：1 无推导或依赖倒置／3 断点≥2／5 链条全但常识顺推无反例检验／7 主要反例已排除边界可见／9 反例穷举边界显式
- **证据可回指性（15%）**：**先判文体再套基准**（v12.5.8 修订）——研究型 须验自采数据来源·样本·方法·参数可复现；理论建构型 须验理论资源版本可核验；观点评论型／考据型 不要求参考文献表，但引用具体数据、文件、报告者须标明来源。
  **禁以引证条数或引证密度加分**（依据：实测引证密度与刊物层级 ρ＝−0.632，负相关）。
- **规范合规性（15%，规则轨）**：1 硬红线触犯未处置／3 红线过但体例多处不合／5 红线体例过但自查打勾式／7 各红线 grep 实测留痕／9 附改前改后对照
- **可读性（10%）**：1 无头栏长平铺／3 有头栏决策点不显式／5 结构可读判断淹没／7 三行结论卡在位段比≤1:3／9 可扫读抓要
- **适配度（10%）**：1 与期刊明显冲突／3 未对准具体刊物／5 对上主要要求细项未校／7 逐条对上作者须知／9 做过样例件级比对。
  **不得以刊物层级为评分输入**（否则等于把外部锚偷运回评分内部，检验自我证成）。

## 四、判据（校准协议第 4 条 ＋ 第 7 条，**仅对 blind 面板生效**）

- **主判据**：Spearman ρ ≥ 0.8（篇内六维均值或逐维均值达标即算）
- **辅助一**：加权总分**最大分差** ≤ 2
- **辅助二**：加权总分**平均绝对分差** ≤ 1（防“系统性偏移”——整体差一档时 ρ 仍可 1.0）
- **严重度差**：须单列 owner−agent 的档序差均值（正＝用户偏宽，负＝用户偏严）
- **qwk**：仅参考。n<15 时因小样本＋系统偏移统计不稳定（CL-07 实测 qwk=−0.37 而 ρ=0.98），**不得作放行判据**
- **最低有效样本数（v12.5.11 · 用户裁定）**：篇内 ρ／逐维 ρ 皆为**均值型判据**，须由“多数”单元支撑。
  有效单元不足门槛 **need = max(3, ⌊n/2⌋+1)** 时，该判据**不取得放行资格**——数值照报，**但不进判据门**，
  输出标 `[INSUFFICIENT]`。**性质区分**：这是“证据不足”，不是“尺度不合”，二者不可混读。

## 五、纪律

1. 独立重读原文判档，**勿对齐 agent 分**；跨 ≥2 档分歧入 `data/divergence-bank.md`。
2. 理由—分数自洽：填分时在脑中过一遍“此理由按锚点应落哪档”，避免理由与分跨档。
3. 同稿同维两评审应落同档或相邻档；分差 >2 的稿段请注明归因（锚点歧义／维度划分／稿本身临界）。
4. **real 面板另加一条**：只按稿内完成度评，勿以“此稿发在哪本刊”反推分数。
   若察觉自己在按层级给分，请立即停手并告知——该份数据即失效。
5. **关于“六维全同分”（v12.5.11 增）——机制告知，但不得迎合**：
   若某篇六维打同一档（或某维全篇同一档），该单元**秩相关未定义，会被剔除**，
   不计入篇内 ρ 的有效样本；剔除过多则该判据失去放行资格（见 §四）。
   上一轮（CL-11）六篇中，owner 侧 3 篇（B10／B12／B3，中高档段）与 agent 侧 2 篇（B6／B8，低段）
   为常向量——**分属两侧且零重叠**，故双侧非退化仅 1／6，即因此失效。
   **但请务必按真实判断打分**——若某篇在您看来确实各维齐平，就如实打同分，
   **不要为了“凑出差异”而人为调整任何一维**。人为制造排序比样本不足更糟：
   它会让 ρ 虚高，把“假一致”当成“共用一把尺”。

6. **粒度声明（v12.5.12 增）**：提交时请一并说明本次的评分粒度——
   `per-dim` 逐维独立判档 ／ `flat` 整篇定档、各维基本同分 ／ `mixed` 部分篇逐维、部分篇整篇。
   三者**皆为合法粒度**，粗粒度是诚实的表达，不受歧视（亦不因此要求重评）。
   粒度只影响“资格不足”时的**归因**——flat／mixed → 判据结构性不适用（下一步**换判据**）；
   未声明／per-dim → 证据不足（下一步**补样本**）；**不改变门槛与判定**。
   若您实际按整篇定档而**未声明**，系统会按“需补样本”归因，导致下一步动作走错方向，请务必声明。
