# 认知建构层运行协议（C 层运行协议 · v11.0）

> **定位**：C 层的“接口层”——定义十一道工序如何衔接、产物如何流转、守门如何判定、回退如何重跑。让 C 层从“十一道独立工序”变成“一条流水线”。
> **一句话**：每道工序吃进什么、吐出什么、怎么验货、不合格怎么办——四件事说清，流水线就通了。
> **加载时机**：进入 C 层（C1 选题）时加载；C9 判定回退时必查。
> **关系**：本协议是 C 层骨架的运行时补充——骨架只管工序定义与守门，本协议管工序之间的接口。交接件的字段模板见 `接口件契约.md`；守门打分见 `评分维度库.md`。S 层论证锚定卡是 C 层的唯一输入口（其模板见 P0）。
> **深度档**：每工序按深度预算表（SKILL.md 第五节）取默认档，档位变化必须显式标注（卡点自检驱动）。

## 一、工序产物契约表（十一道工序的接口）

> **契约**：每道工序是一个“供应商”，向下一道交付约定格式的产物。交接不看口头，看编号与接口件。
> **失败判据** = 卡点自检不通过即判失败（见第三节清单）。

| 工序 | 输入（来自） | 核心执行 | 产出（传给） | 深度档 | 失败判据 | 守门 | 放行后 |
|---|---|---|---|---|---|---|---|
| **C1** 选题 | 定稿契约+P0 锚定卡 | 四环节：态势→推荐→评测→打磨 | 选题卡 P1 | 🔴 | 评测三维不过 | ③ | → C2 |
| **C2** 材料建档 | 选题卡+P0 | 检索→采集→建档 | 总成卡/账本 P2 | 🟢/🟡 | 覆盖率不达标 | ④ | → C3 |
| **C3** 综述 | 总成卡 | 归类→评述→缺口收束（综述引擎引擎，M1/M2 双模式） | 综述稿+**缺口卡** P3 | 🟡 起（缺口升 🔴） | 承重席缺漏/弱缺口表述 | ⑤ | → C4 |
| **C4** 论证框架 | 缺口卡+总成卡 | 理论框架+概念收敛+模型+RQ 链+骨架确认+摘要结语初拟 | 框架包 P4（框架+模型卡+结构定案卡+素材分配表+摘要结语初稿） | 🔴 | 概念超预算/RQ 链不闭/镜像不对称 | ⑥ | → C5 |
| **C5** 材料填充 | 框架包+P2 | 按分配表装配，产出块状粗稿 | 粗稿+**装配核对表** P5 | 🟡 | 证据链 <2 条或不可回指 | ⑦ | → C6 |
| **C6** 正式撰写 | 粗稿+核对表 | 语言环节（只动语言不动论点），对照期刊画像 | 语言定稿稿 P6 | 🟡 | style-rules 自查不过/五维 <35 | ⑧ | → C7 |
| **C7** 净化 | 语言定稿稿 | 量化扫描+AI 特征清查 | 净化报告+修订稿 P7 | 🟢 | 禁词未清零/密度超限 | ⑨ | → C8 |
| **C8** 格式校验 | 修订稿 | GB/T 7714+图表编号+体例 | 格式核验单+合规稿 P8 | 🟢 | 引用格式硬伤 | ⑩ | → C9 |
| **C9** 联合评审 | 合规稿+框架包 | 五席评审小组（Field Analyst 前置＋五席独立评审＋Synthesizer 收口）+回退判定 | 审稿报告 P9 | 🔴 | P1 致命项未清零 | ⑪ | → C10 或回退 |
| **C10** 修改沟通 | 审稿报告 | 逐条修改-沟通循环 | 确稿令+修订对照 P10 | 视情况 | 无用户确稿令 | ⑫ | → C11 |
| **C11** 最终精校 | 确稿 | 逐句终校+摘要终定+心得三问+归档 | 终稿+全流程档案 P11 | 🟡 | 〔待核〕未清零/档案不全 | ⑬ | → E 层 |

**依赖单向性**：后一道只消费前一道产物，不回头改前一道（除非 C9 判定回退）。产物之间是“流水线输送”，不是“所有人共享草稿箱”。

## 二、产物交接格式（十一个产物的标准模板）

> 每个产物**带号流转**：编号规则 `{工序代码}-{序号}`（如 C3-001）。交接引用编号，不靠口头描述。S 层双产物：**P0**（论证锚定卡，C1 唯一输入口）+ **P0-R**（认知演进挂载结果稿，用户答卷）。产物头栏一律：一句话结论置顶 + 决策点显式 + 证据后置。

### P0 论证锚定卡（S 产出，C 层唯一输入口）
```markdown
论证锚定卡 P0-{序号}：{稿件名}
档位 ｜ 锚定结论 ｜ 思考深度 🔴 ｜ 论证基调
元层诊断 / 核心判断句 / 攻击清单 / 论证路径 / 推理依据（标来源环）/ 验证行 / 偏好清单（→C11 并入档案）
```

### P1 选题卡（C1）
```markdown
选题卡 C1-{序号}：{定稿选题}
四环节记录：态势→推荐→评测→打磨 ｜ 定稿选题+一句话定位 ｜ 备选题
守门③：评测三维通过 → 放行 C2
```

### P2 总成卡/账本（C2）
```markdown
账本 C2-{序号}：{账本类型}
客观索引（只描述不归类）+ 提醒区 + 补检任务单 ｜ 覆盖率 = {n}%（门槛达标/未达标）
```

### P3 综述稿 + 缺口卡（C3）
```markdown
综述稿 C3-{序号}：M1 嵌入式 / M2 完整式
缺口卡（C3→C4 接口件）：缺口陈述（强表述）+ 证据链（≥2 条可回指）+ 本文入位声明 + 承重席清单
守门⑤：承重席全覆盖+评分留痕 → 放行 C4
```

### P4 框架包（C4）
```markdown
框架包 C4-{序号}：
理论框架定位（主框架价值与不足+辅助理论批判性补充）｜ 概念 ≤3（新概念附谱系定位）｜ 机制模型 ｜ RQ 链
结构定案卡：节次方案+每节任务/字数/承重素材映射 ｜ 摘要/关键词/结语初稿（终定在 C11）
守门⑥：概念预算+RQ 闭合+镜像对称 → 放行 C5
```

### P5 块状粗稿 + 装配核对表（C5）
```markdown
粗稿 C5-{序号}：允许语言粗糙
装配核对表：每节每段｜主张句｜证据链 id（≥2 可回指）｜评析句｜接榫句｜勾选
守门⑦：核对表全勾 → 内容冻结 → 放行 C6
```

### P6 语言定稿稿（C6）
```markdown
语言定稿稿 C6-{序号}：style-rules 自查逐项留痕 ｜ 写作状态摘要（已产出/已引用/待确认/下节预告）
守门⑧：五维 ≥35/50 → 放行 C7
```

### P7 净化报告（C7）
```markdown
净化报告 C7-{序号}：禁词/破折号/句式/段落比 数字前后对照表
查重栏固定标注：“外部人工环节，未执行自动查重”
守门⑨：禁词零命中 → 放行 C8
```

### P8 格式核验单（C8）
```markdown
格式核验单 C8-{序号}：GB/T 7714 逐条核对 ｜ 图表编号 ｜ 体例统一

```

### P9 审稿报告（C9）
```markdown
审稿报告 C9-{序号}：五席评审清单（EIC/方法学/领域/跨视角/DA 各席意见＋Synthesizer 收口 Editorial Decision 与 Revision Roadmap）｜ P1/P2/P3 分级逐条可回指
```

## 三、卡点自检程序化清单（怎么算通过）

| 守门 | 判据标准 | 程序化自检 | 检测到缺失时 |
|---|---|---|---|
| **②**（S） | 七要素+双产出 | 档位变量比对/权重/情感目标/冲突/判断句/路径/验证行+P0-R 交付 | 回 O2；锚点缺失 → S 重跑 |
| **③**（C1） | 评测三维通过 | 新颖性/价值/可行性逐维核 + 标题打磨完成 | 换候选或方向；方向级不过回 O2 |
| **④**（C2） | 覆盖率 ≥门槛（学术 ≥80%） | 覆盖率计数 + 关键论点须高可信证据 | 补证据补账本 |
| **⑤**（C3） | 承重席全覆盖+强缺口+评分 ≥7 | 承重席逐条对卡；缺口表述扫描（禁“研究较少”）；评分维度库打分留痕 | 缺漏回评述补引；缺口弱→重做合观推导 |
| **⑥**（C4） | 概念≤3+RQ 闭+镜像对称 | 概念计数；RQ 链逐问核对承接面；开头承诺↔结尾回应 1:1 连线 | 概念合并；RQ 补链；补映射 |
| **⑦**（C5） | 装配核对表全勾 | 逐段核证据链 ≥2 条可回指 | 补证据或退回 C2/C4 |
| **⑧**（C6） | 五维 ≥35/50+自查留痕 | 五维打分；style-rules 逐项留痕（禁打勾了事）；字数 ±10% | 按缺项回对应板块；论证乏力升 🔴 |
| **⑨**（C7） | 禁词零命中+密度达标 | 数字前后对照逐项核 | 未达标不得放行 |
| **⑩**（C8） | 引用格式全过 | GB/T 7714 逐条；图表编号连号 | 逐条修正 |
| **⑪**（C9） | P1 清零 | 五席评审清单逐条裁决（SPLIT 与 DA-CRITICAL 呈用户）；致命项必须已修复验证 | 修复后按分档重跑（首评后修改轮走 quick/re-review；致命项修复重跑 full） |
| **⑫**（C10） | 确稿令生效 | 用户签字在案 | 继续修改-沟通循环 |
| **⑬**（C11） | 待核清零+档案齐 | 〔待核〕扫描；看板+流水+产物齐套 | 未清零不得交付 |

**深度升级触发**：检测到“概念未定义即使用/证据链断/关键论点无支撑/自洽性存疑”→ 该工序深度升一档，重跑产物，标注环节卡审计字段。

## 四、回退重跑协议

> **原则**：回退 = 有记录的返工，不是推倒重来。**登记不惩罚**：合法回退线内回退记入决策流水，不作污点记录——防“为不回退而隐瞒问题”。

**第一步 · 标记**：进度卡打 `✗` + 决策流水登记原因 + 目标环节 + 深度变化。
**第二步 · 冻结与保留**：目标环节之后的产物冻结（保留现场，视为失效）；之前的保留作重跑输入。

**第三步 · 重跑路径**：

| 回退到 | 重跑动作 | 重过守门 | 后续 |
|---|---|---|---|
| O2（目标/判断句错位） | 重出锚定卡 | ② | S 重跑，C1-C11 全部重跑 |
| C1（选题不当） | 重做四环节 | ③ | 重跑 C2-C11 |
| C2（证据不足） | 补证据补账本 | ④ | 重跑 C3-C11 |
| C3（缺口不成立/综述缺漏） | 重做归类评述/缺口收束 | ⑤ | 重跑 C4-C11 |
| C4（框架/概念/模型问题） | 改框架改模型 | ⑥ | 重跑 C5-C11 |
| C5（装配问题） | 补装配 | ⑦ | 重跑 C6-C11 |
| C6（表达问题） | 改表达 | ⑧ | 重跑 C7-C11 |
| C7（净化遗漏） | 补扫描 | ⑨ | 重跑 C8-C11 |

**第四步 · 轮次纪律**：每轮更新修复跟踪表；修改后必须重跑 C9 全评审；**3 轮未过 → 结构性诊断**（问题在 O2 锚定或 C1 选题，换重跑路径，禁止在表达上打转）。

**每论文一份决策流水**（GATE 裁决按时间序追加，只增不删）：
```markdown

- 裁决内容：{}
```

3. 深度变化写进审计行；决策流水与看板归档于 C11 全流程档案

## 六、运行铁律（六条）

1. **带号流转**：产物有编号，交接引用编号，不靠口头描述
2. **接口件放行**：交接件字段不齐，守门不得放行（见接口件契约）
3. **守门必评分**：无评分表的 GATE 视为未执行守门（见评分维度库）
4. **回退必登记**：决策流水记录原因与目标；登记不惩罚
5. **单向依赖**：后一道只消费前一道产物；除回退外不回头改
6. **深度受控**：按预算表取档，升级由卡点自检触发，显式标注可审计
