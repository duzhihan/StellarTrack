# M-K-T 三库管理规范（准入 · 修改 · 入口归类）

> 定版：2026-08-23（奉用户令成文）｜上位文件：SKILL.md v12.1 第五节路由规则
> 三库定位一句话：**M 管每步怎么干，K 管材料从哪来，T 管用什么家伙。**

## 一、M 方法库（references/methods/）

### 准入（入库四闸）

1. **复用闸**：同一打法跨 ≥2 稿复用，或经实战纠偏 ≥1 次——单一场景的一次性技巧不入
2. **范式闸**：标明适用范式；实证轨卡仅实证稿加载，理论稿不得误载
3. **格式闸**：六字段齐备（名称/适用范式/适用工序/核心流程要点/自检清单/来源日期），缺一退回
4. **裁决闸**：用户拍板方可入册；助手只做整理与预判

### 卡种二 · 母版适配卡（2026-08-23 增设，用户照准三层分离方案）

- 用途：非学术档位的 C1-C11 逐格装载声明（功能动词翻译＋默认引擎＋守门深度）
- 格式四字段：档位名／C1-C11 逐格装载表／守门深度声明／来源日期；模板见《C环节母版适配_工序动词表与守门分级.md》
- 准入：沿用四闸（复用闸对首稿豁免——档位立卡即入）；修改走 E 层置信程序同卡种一
- 现状：教学档已补全为正式档位（v12.6 修订，见 `references/教学档工作流.md`），传播/规范档随首稿实测补齐

### 修改

- 卡是“执行标准”，修改=改标准 → 必须走 E 层置信程序：实战纠偏证据累计 ≥3 分方可改卡，否则在卡尾加〔备注〕不动正文
- 废卡不删除，移入 `methods/_archive/` 并在卡头标注废止日期与替代卡

## 二、K 知识库（LLM-Wiki :19828）

### 准入（写入侧·知识库读写通道）

1. 来源可回指（文章链接/文献题录/稿件产物），无源不入
2. 条目=线索格式：摘要 ≤5 句＋[[wikilink]] 关联＋来源日期；**不预存结论**
3. 星躔产物回流知识库须用户点名，不自动回写

### 修改

- 条目只增不改（新认识新增条目并 [[关联]] 旧条目，保留认知轨迹）
- 铁律三条常驻：不预存不预载／线索非结论／回源走 claim-audit；服务不可达按降级条款跳过不阻塞
- **双外接（20260823 补遗落）**：Obsidian=主战场本地载体（四层结构 RAW→Source→Wiki→MOC，判断卡制详见本文档“知识库 K”节；K 库设计档案《K库知识架构_v1》属作者本地工程档案，未随包发布）；ima=移动采集前端，只收不炼，定期导出灌 L0。三口分工：ima 管收、知识库读写窗管炼、API 管查

### K 库双轨（v12.6 新增 · 保证零外接可用）

- **内置基础库（默认·随包·零依赖）**：`data/kbase/` 文件式四层（RAW→Source→Wiki→MOC）＋分区映射；写作、沉淀、检索全部走随包文件，**不依赖 Obsidian/知识库服务/移动采集端即可全功能运行**。骨架与条目格式见该目录 README。
- **外接增强库（可选）**：Obsidian（双链图谱/全文检索/移动同步）、知识库服务（语义查询/API）、移动采集端（随手采集）——优点与安装配置见《三库使用与积累指南》第四节。
- **同步原则**：启用外接后，基础库条目可批量导入外接库；**双向以 `data/kbase/` 为源**，基础库不失效，外接为视图增强。

## 三、T 工具箱（档位指令包内嵌 skill）

### 定位升级（v12.6.1 · 全生命周期治理）

> **台账唯一权威源**：外部 skill 接触台账 = `data/skill-tracker.md`（唯一权威，凡接触过的 skill 一律登记，含拆解未装类）；注册表（在用引擎）与待加载清单（候选池）均为其投影，不另立权威。**收到外部 skill 第一步＝登记台账**（十字段字段，见该文件“字段说明”）。

### 准入（转正四步）

1. **登记**：候选进 `data/skill-tracker.md`（唯一权威），只登记不安装；**台账十字段缺一不登记**（标识/开发者/来源链接/许可/版本标识/维护活跃度/star(参考)/原理一句话/处置状态/实用证据）
2. **审计**：skills-security-check 全量安全审查（SKILL.md＋scripts/ 全部捆绑文件），P0 风险一票否决
3. **归属**：判定档位归属（学术/传播/规范/申报/创作）与工序落点，检查与已有资产重叠度（已有互证→不引入）
4. **裁决**：用户批准 → 安装 → 登记转正日期 → 更新台账状态 → 从待载清单移除 → 写入对应档位工作流指令包

### 溯源纪律

- 转正后溯源信息随行：台账十字段完整；skill 目录内 SKILL.md 头部补注释块（来源/许可/入库日期）
- M 方法卡同理：来源日期字段已内置六字段制，新增要求——来源须可回指到原文链接或稿件编号
- 已有存量资产补标：随季度盘点逐个补齐，不集中运动式清理（台账“存量补全”节列清单）

### 实用性评估（v12.6.1 · 不以 star 论英雄）

**决策依据一句话：实测/实战证据 > 上游活跃度 > 文档质量 > star（仅初始排序参考，不决策）。**

- **实用证据制**：每个 skill 的“实用证据”列记录真实使用痕迹（实测日期／实战稿号／交叉命中），证据等级沿用置信加权制（实战 2 分／实测 1.5 分／交叉命中 1 分／自我 0.5 分）；每稿 E1 沉淀时回填调用过的引擎
- **五态状态机**：

| 状态 | 条件 | 处置 |
|---|---|---|
| 拆解未装 | 只取思想不装引擎（拆解型） | 台账 D 组留档，拆解产物并入方法论/规则库 |
| 试挂 | 审计通过、待实战 | 注册表登记〔试挂〕，≥1 稿实战后评估 |
| 转正 | 实用证据 ≥3 分（置信加权）或用户拍板 | 注册表转正，档位工作流写入 |
| 休眠 | 转正/试挂后 ≥6 个月零使用 | 降为参考，不占注册表主位 |
| 归档 | 休眠 ≥6 个月 | 移入 `references/archive/`，台账留痕 |

### 自动更新检查（v12.6.1 · skill_updater.py）

- **工具**：`data/skill_updater.py`（随包 05 分区）——读台账“有 GitHub 仓库＋已装”条目，经 GitHub API 查上游最新 commit hash＋日期，对比台账版本 pin，输出三态表：**可更新／已是最新／不可达（离线降级，不阻塞）**
- **更新动作必须人工**：下载新版本 → **重过第 2 步审计**（防上游被投毒/许可变更）→ 更新台账版本标识 → 重跑体检。**禁止自动拉取上游更新**
- **接入**：00B 体检文档“Skill 更新检查”节（用户侧例行：`python data/skill_updater.py`）；许可变更（如 NC→商用限制）即触发复审

### 修改

- 工具升级/替换须重过第 2 步审计；许可变更（如 NC→商用限制）即触发复审
- 移除工具同步清理指令包引用，防悬空调用

## 四、入口归类总表（WorkBuddy 常驻对话窗口 × K/T/M）

> **入口性质（用户勘误 2026-08-23）**：以下均为 WorkBuddy 的**常驻对话窗口**——每个窗口挂一个角色 skill、长期续聊，是用户工作台的分域工作台；不是插件、不占 skill 编制。

### 4.2 数据流向一句话

**供给窗**（札记供给／创意研究／学术理论／灵感捕获）→ **知识库读写窗**（整理入 K）→ **星躔窗**（四挂载点按需取用）→ 产物回流仍须经知识库读写通道、不自动回写。写作类任务不分域，一律星躔 O1 进、按档位出；灵感捕获窗产出的灵感走暂存箱直供 O 层，不经 K 预存。

> 窗口实体名（如 azure-dragon-creative、white-tiger-research）为 skill 安装标识，功能名见上表；全景图中各供给窗合并为一个“WorkBuddy 对话窗集合”框表示，窗口明细以本表为准。

## 五、维护纪律

1. 本规范为三库唯一管理文件；SKILL.md 只留加载规则与铁律，不重复准入细节
2. 每次入库/转正/废立在决策流水记一行（D-编号制）
3. 季度盘点（随 E2 复盘）：M 卡使用率、K 库死链、T 工具许可变更
