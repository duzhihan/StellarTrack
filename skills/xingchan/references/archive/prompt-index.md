# 引擎清单与调用协议

> 定位：毕方操作层所有外部引擎的调用协议总入口。
> 加载时机：各引擎在对应环节自动触发，无需手动加载全文。
> 降级策略：引擎不可用时，自动降级为内置模板（模板名见各引擎降级列）。

---

## 一、引擎矩阵

| 引擎 | 功能 | 调用环节 | 触发条件 | 降级策略 |
|---|---|---|---|---|
| **谛听** | 六环认知（元层诊断→锚定→对抗→拆解→表达→成型→验证） | G0（强制）、G4（方向校验）、G6（根因分析） | 进入G0/G4不通过/G6沉淀 | 内置五问模板（目的/读者/身份/完成标准/难点） |
| **cnki-deepsearch** | 知网三层检索（关键词→引文→被引回溯） | G1（学术档、申报档全深度管线） | 档位=学术/申报 × 时间≥1周 | 人工知网节点（手动检索后粘贴结果） |
| **离朱** | 问题驱动综述（研究问题→文献池→理论框架→述评） | G1（学术档标准及以上） | 档位=学术 × 时间≥1周 | AI 手动综述（用殿主偏好的"述4评6"结构） |
| **雕龙叙事** | 叙事骨架（认知→塑形→写作→质检→视觉五阶段） | G2（传播档） | 档位=传播 | 内置六步模板（场景→冲突→转折→解决方案→价值→行动号召） |
| **五层清稿管线** | 去AI味（L1通用词/L2短语替换/L3句式反模式/L4结构反模式/L5AI痕迹扫描） | 全管线（自动） | 全部输出自动触发 | 旧版词表过滤（ai-vocabulary-filter.md Layer 1-2） |

## 二、谛听调用协议

### 2.1 触发时机

| 环节 | 触发条件 | 调用模式 | 输出 |
|---|---|---|---|
| G0 | 强制启动 | 完整六环 | 锚定卡（七字段） |
| G4 | 审稿不通过 | 方向校验（仅根因分析） | 问题归属判定（G0/G1/G2/G3/G4） |
| G6 | 沉淀决策争议 | 深度分析 | 沉淀决策建议 |

### 2.2 六环流程

1. **元层诊断**：问题分类（决策/创作/分析/审查）+ 交付类型 + 模式选择 + 约束条件
2. **锚定**：核心矛盾识别（一句话说清"什么是这个问题的关键分歧"）
3. **对抗**：列出正反两方论证，不预设立场
4. **拆解**：分解为可操作的子问题/子步骤
5. **表达**：锁定交付格式（表格/清单/判断句/直接回答）
6. **成型+验证**：输出结论 + 逻辑自洽检查 + 韧性测试（最脆假设是什么）

### 2.3 降级（内置五问模板）

当谛听不可用时，用以下五问替代：

```
1. 要解决/传达什么？
2. 读者是谁？他们的前置知识/期望是什么？
3. 我是谁在说？作者身份/立场/权威来源是什么？
4. 什么算完成？质量标准/验收条件是什么？
5. 难点在哪？已知风险/不确定因素是什么？
```

## 三、cnki-deepsearch 调用协议

### 3.1 触发条件

档位=学术/申报 × 时间≥1周（全深度管线）。≤3天轻量管线跳过，1周标准管线可选。

### 3.2 三层检索结构

| 层 | 操作 | 产出 | 时间估算 |
|---|---|---|---|
| 第一层（关键词） | 核心概念→同义扩展→中英文对照→知网检索 | 初级文献池（20-30篇） | 5-10分钟 |
| 第二层（引文） | 关键文献的引用网络→被引频次排序→高被引+最新文献 | 精炼文献池（10-15篇） | 5-10分钟 |
| 第三层（被引回溯） | 关键观点的源头文献→引用链条→研究脉络 | 核心文献与理论脉络 | 5-10分钟 |

### 3.3 降级

cnki-deepsearch 不可用时，切换为人工知网节点：告诉殿主"知网检索不可用，请手动在知网检索以下关键词：[列出关键词]，将结果粘贴到这里，我会继续处理。"

## 四、离朱调用协议

### 4.1 触发条件

档位=学术 × 时间≥1周。G1 环节，材料工程阶段。

### 4.2 核心流程

1. **研究问题锚定**：从锚定卡提取研究问题，一句话锁死
2. **文献池构建**：从 cnki-deepsearch 产出或人工输入中提取文献
3. **理论框架映射**：文献分类→理论取向识别→框架缺口分析
4. **述评写作**：述4评6——述（4成：文献梳理、分类、共识与分歧）+ 评（6成：批判性分析、研究空白、理论贡献）
5. **研究缺口声明**：一句话说清"已有研究没做什么，为什么这重要"

### 4.3 降级

离朱不可用时，使用 AI 手动综述：按殿主偏好的"述4评6"结构，用判断句开段，每段先述后评，不出现"综上所述""值得注意的是"等套话。

## 五、雕龙叙事调用协议

### 5.1 触发条件

档位=传播。G2 结构设计环节自动触发。

### 5.2 五阶段叙事骨架

| 阶段 | 问题 | 产出 |
|---|---|---|
| 认知（C） | 读者关心什么？核心矛盾是什么？ | 读者画像+矛盾定位 |
| 塑形（S） | 怎么讲才能让读者听懂？ | 叙事路线图 |
| 写作（W） | 逐段实现 | 初稿 |
| 质检（Q） | 各维度审核 | 审稿报告 |
| 视觉（V） | 封面/配图/版式建议 | 发布就绪包 |

### 5.3 降级

雕龙叙事不可用时，使用内置六步模板：

```
场景 → 冲突 → 转折 → 解决方案 → 价值点 → 行动号召
```

## 六、五层清稿管线调用协议

### 6.1 触发条件

全部输出自动触发。不可跳过。

### 6.2 五层结构

| 层 | 检查对象 | 规则来源 | 处理方式 |
|---|---|---|---|
| L1 通用词过滤 | "基于""关于""涉及""通过"等高频泛词 | ai-vocabulary-filter.md Layer 1 | 替换为具体动词 |
| L2 短语替换 | "值得注意的是""本文认为""综上所述"等套话 | ai-vocabulary-filter.md Layer 2 | 删除或替换为具体转折 |
| L3 句式反模式 | "不仅……而且……""从X到Y"等固定句式 | ai-vocabulary-filter.md Layer 3 | 拆解为独立短句 |
| L4 结构反模式 | "不是X而是Y"密度过高、判断句缺失 | ai-vocabulary-filter.md Layer 4 | 调整段落结构 |
| L5 AI痕迹扫描 | 全文综合判断（修饰词密度/句长分布/模板识别） | ai-vocabulary-filter.md Layer 5 | 标记并局部重写 |

### 6.3 降级

五层清稿管线不可用时，降级为旧版词表过滤（仅 L1-L2），标注"降级：仅完成基础过滤"。

## 七、引擎调用规则

1. **并行调用**：互不依赖的引擎可以在同一轮次内同时触发（如 G1 阶段 cnki-deepsearch 与离朱可以并行）
2. **顺序依赖**：离朱依赖 cnki-deepsearch 的产出；雕龙叙事依赖 G0 锚定卡
3. **降级传播**：引擎降级后，输出必须标注降级状态（如"⚠️ 降级：cnki-deepsearch 不可用，切换为人工知网节点"）
4. **失败截止**：同一引擎连续 3 次调用失败→永久降级为本会话的人工模式，不再重试
