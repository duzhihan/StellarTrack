# 接口件契约（十一道门交接件模板）

> **原则**：交接不看口头，看接口件。下一工序只认契约内字段齐全的产物；缺字段守门不放行。
> **通用头栏（每份产物必带）**：一句话结论置顶 + 决策点显式标出 + 过程证据后置（读者导向，v11.0 强制）＋**生效性留痕四行**（v12.5.0 强制，见文末 §生效性留痕）。
> **改契约须跑测试网（v12.5.4 强制）**：本文件**任何改动后**必须跑 `data/contract_testnet.py`，**全绿方可提交**（退出码非 0 即阻断）。防两类事故：字段被静默删除、新增字段回归丢失（如 v12.5.1 的“来源分级列”“冲突并列登记”）。测试网自身亦须拿反例自测——只跑正式件全绿不足以证明有效。

## 关键接口件详规

### 缺口卡（C3→C4）

```markdown
# 缺口卡 {论文号}
## 缺口陈述（一句话强表述，禁"研究较少"弱表述）
## 证据链
- {asset_id}｜{该文献止步处}｜{未答的问题侧面}
- （≥2 条；缺口须为四类评述合观的推导结论，非检索零命中转写）
## 本文入位声明（本文以什么概念装置进入这道缺口）
## 承重席清单（全部入文素材 id + 强度）
```

### 装配核对表（C5→C6 内容冻结门）

```markdown
| 节·段 | 主张句 | 证据链 id | 评析句 | 接榫句 | 勾选 |
|---|---|---|---|---|---|
```

全勾方可进 C6；进 C6 后内容冻结，发现内容问题须在决策流水登记后回退 C5。

### 净化报告（C7→C8）

```markdown
| 指标 | 改前 | 改后 | 判据 |
|---|---|---|---|
| 禁词命中 | n | 0 | 零命中 |
| 破折号密度 | x/千字 | y | ≤2/千字 |
| "不是X而是Y" | n | m | ≤8/篇 |
| 相邻段落字数比最大值 | x | y | ≤1:3 |
| **命中并修改处数** | — | n | **0 处须显式写“本工序本轮无作用”**，禁止静默通过 |
```

查重栏固定标注：“外部人工环节，未执行自动查重”。

## 生效性留痕（v12.5.0 · 通用 · 每件必附）

> **为什么**：原契约只管“字段齐不齐”（**存在性**），管不住“这一步是不是真起了作用”。实测教训——**“做过”≠“生效”，“不报错”≠“正常”**。故自 v12.5.0 起，每份接口件在通用头栏与必含字段之外，**另附四行生效性留痕**；缺失者守门不放行。

```markdown
## 生效性留痕
- 作用计数：本工序改动 {X} 处 ／ 新增 {Y} 条 ／ 剔除 {Z} 条
- 零作用声明：{有 — 原因：… ／ 无}
- 依据轮次：上游 {产物号} {轮次/版本标记} 与当前稿 {轮次} 一致 ✓
- 实测数字：{grep／wordcount 原始输出，禁转述}
```

| 字段 | 判据 | 不通过的处置 |
|---|---|---|
| 作用计数 | 与工序应产生的改动量相称；**恒为正且数值稳定得不合理 → 判计数未反映真实作用**，须复核计数口径 | 回本工序重做并说明口径 |
| 零作用声明 | 计数为 0 时**必须**出现该行且附原因（如“本轮无该类型问题”）；**静默通过判违规** | 补声明后方可放行 |
| 依据轮次 | 与当前稿轮次／版本标记一致（防“用旧稿评新稿”——缓存污染是评分错乱的第一原因） | 用错轮次者，评审作废重跑 |
| 实测数字 | 声明“已清零／已通过”的项，附工具实测原件 | 无实测者判未执行 |

**与评分表的关系**：生效性三问同时是 `references/评分维度库.md` 评分表的必填栏（见该文件第四节模板）；两处填同一组数字，不重复劳动。
