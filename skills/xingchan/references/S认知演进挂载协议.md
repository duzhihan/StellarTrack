## 一、挂载原则（双方铁律融合）

| 认知演进挂载铁律 | 星躔呼应 | 融合后 S 铁律 |
|---|---|---|
| 一次一问 | 场景识别已用尽提问额度（O1 ≤2 轮） | S 每步 ≤1 问；元层批量呈现除外 |
| 不替拍板 | 思想与决策永远属于用户 | 一切判断给“候选 + 理由”，用户拍板 |
| 95% 信心即停 | O2 已锁十变量 | 澄清到可执行即停，不无限追问 |
| 环间可回溯 | 守门②不过 → 回 O2 或重跑 S 环节 | 回溯标注“回溯修正：X→Y”，不重复已确认部分 |
| 思考必落产物 | 核心原则 6（思考必落产物） | 所有认知演进挂载结论必须写入 P0 论证锚定卡 |
| 元层 ≤1 轮 | O2 已做 Before/After 确认 | 元层诊断一次呈现，不轮询 |
| 诚实标注不确定 | 锚定卡待确认项机制 | 信息不足明确假设，标注〔假设〕 |
| 确认必回显 | C5 打磨的“本稿偏好清单”+ thinking-protocols 持久档案 | 每个确认点选择后回显“选择即偏好”→ 双写：本稿偏好清单(→P5) + profile/traces/perspectives 持久化（越写越懂用户） |

**定位边界**：S 层是**任务级一次全认知演进挂载**（每稿只跑一次，但**一次 ≠ 一笔带过**——这一次要把六环完整、多轮地走完）；C 层按深度预算表**环节级按需加深**（如 C9 联合评审 🔴 可再借认知演进挂载双向钢人）。S 挂载不替代 C 层环节认知演进挂载，两者正交。

## 二、完整六环 → S 编号（全保留，无裁剪）

> 编号约定：**S1 = 元层诊断**（思考起点，非六环本体但计为首节点）；**S2-S7 = 认知演进挂载六环**（①锚定→②对抗→③拆解→④表达→⑤成型→⑥验证）。

| S 编号 | 认知演进挂载环节 | 星躔 S 动作 | 产出 | 说明 |
|---|---|---|---|---|
| **S1** | **元层诊断** | ① 论证锚定复核（四要素）② **模式选择(选/不选/混合，8 张卡 first-class，默认呈现)** ③ **视角银行检索/入库** ④ 证据基底（≤3 条） | 元层诊断行（P0 头部） | **档位管表达规范、模式管思维框架，二者正交**——模式选择不交给档位“承接”，S1 元层显式呈现；模式库默认可选，非“仅显式点名才启用” |
| **S2** | **①锚定** | 核心判断句——本稿要立住的论点（**一次一问收敛**，顺着回答追问） | 判断句候选 | 对应认知演进挂载“锁目标对象与核心动机” |
| **S3** | **②对抗** | 双向钢人——三个攻击点中**至少一点须为替代解释/竞争框架**（有没有更好的解释能比下去本判断句），禁全是文献新旧式技术挑刺 | 攻击清单 | **🔒 等回答才给判断**：钢人后只问 1 个关键问题，用户答完才定稿判断句；杀不过 → 回 S2 重写（算迭代不算失败，见下方微循环） |
| **S4** | **③拆解** | 论证路径预览——证据→结构两条线（四象限法列 2 维，一次确认）；表达走向不在此预览，锁定权独归 S5 | 路径草图 | 对应认知演进挂载“结构化拆解” |
| **S5** | **④表达** | 论证基调二选一——重论证逻辑 / 重信息密度（**🔒 等选择**） | 基调行 | 只锁基调不锁文风；话术底线归 C6 正式撰写档位指令包 |
| **S6** | **⑤成型** | P0 论证锚定卡完整版（判断句 + 路径 + 推理依据 + 验证行） | **P0 卡** | 推理依据每段标注来源环（呼应认知演进挂载铁律 5） |
| **S7** | **⑥验证** | 轻量 3 项：逻辑自洽 + 韧性（关键假设不成立时表现）+ 可证伪（预设失败信号） | **验证报告（认知演进挂载结果稿内）** | 重量级验证（反事实重推+利益相关者批驳）留 C9 联合评审；**S7 后双产出：P0 卡（进 C 层）+ 认知演进挂载结果稿（交用户），见 9.6** |

> **S2⇄S3 猜想—反驳微循环（v2.2 显影）**：S2 与 S3 不是先后两站，是一个循环——猜想、试杀、回炉。S3 杀过判断句即回 S2 重写，轮次不限，算迭代不算流程失败。攻击清单三路流出：① 回 S2 修正判断句；② 缺口入 S4 路径补强；③ 随 P0 成为 C1 优先补料项。S 层只试杀，终审留 C9 反例自驳与重量级验证。

**深度联动**：S 固定 🔴 high（定案：不可逆性最高、失败成本最高），不走认知演进挂载轻档；若卡点自检发现“核心判断句空洞”，S 内重跑 S2（锚定），不降档。

## 三、确认点节奏（七确认点 S1-S7，走一步停一步）

> 认知演进挂载七确认点 C1-C7 → S 层映射为 **S1-S7**（元层+S2-S7 六环，一一对应，无合并、无收敛）。

| 确认点 | 对应认知演进挂载 | 位置 | 动作 | 类型 |
|---|---|---|---|---|
| **S1 元层诊断** | C1 | 元层后 | 一次呈现：论证锚定复核结论 + 证据基底 → 用户确认/调整 | 🔒 强制（1 轮） |
| **S2 判断句** | C2 | ①锚定后 | 输出判断句候选 + 理由 → 确认或顺着回答追问 | 轻（默认继续） |
| **S3 对抗关键问题** | C3 | ②对抗后 | 输出三攻击点 → **只问 1 个关键问题，等回答后才给最终判断句定稿** | 🔒 强制 |
| **S4 路径确认** | C4 | ③拆解后 | 输出路径草图（证据→结构 2 维）→ 确认或微调 | 轻 |
| **S5 表达基调** | C5 | ④表达后 | 论证基调二选一 → **等选择后再锁定** | 🔒 强制 |
| **S6 成型确认** | C6 | ⑤成型后 | 产出 P0 论证锚定卡完整版 → 确认或调整 | 轻 |
| **S7 验证交付** | C7 | ⑥验证后 | 验证报告（轻量 3 项）→ 直接交付，守门②判定 | 自动 |

**节奏纪律**（呼应认知演进挂载“确认点节奏”）：
1. **强制确认点必须停**（S1 / S3 / S5），不跳过——尤其 S3 未等回答不得给出判断；
2. **轻确认点停一下**，默认继续（S2 / S4 / S6）；
3. 用户说“继续/好”→ 进下一环；“调整 X”→ 回到该环重做；“算了”→ 结束；
4. 每个确认点**最多抛 1 个关键问题**，绝不批量追问（一次一问铁律）；
5. **回显纪律**：S1-S7 每步用户选择后，必须给“选择即偏好”回显（≤2 行），记入本稿偏好清单。示例：“您确认‘重论证逻辑’，意味着这篇要跟审稿人硬碰硬——信息密度让位给论证纵深”。

## 四、全环节追问化（每环都是对话，不是宣读）

> 这是认知演进挂载的魂，v1.0 丢了，v2.0 显式补回，v2.1 沿用。**S 的每一环都不是系统单方面输出结论，而是提问驱动：先问 → 听答 → 再推进。**

| S 环节 | 追问要点（示例问法） | 原则 |
|---|---|---|
| S1 元层 | 论证锚定复核结论 →“四要素里哪条您觉得没锁死？” | 1 问 |
| S2 锚定 | “这篇最关键的矛盾/对象是什么？顺着回答追问” | 1-3 问 |
| S3 对抗 | 双向钢人后**只问 1 个关键问题**，等回答再给判断 | 1 问 |
| S4 拆解 | “证据、结构两条线草案已列——哪条要调整？（基调下一问单独锁）” | 1-3 问 |
| S5 表达 | 论证基调二选一 → 等选择后再锁定 | 1 问 |
| S6 成型 | 方案关键取舍逐点问：“A 还是 B？”（≤3 问） | 1-3 问 |
| S7 验证 | “最可能让论证失效的假设是什么？”（预设失败信号） | 1 问 |

**原则**：
1. 每环至少 1 个提问、最多 3 个，**答完才推进**；
2. 系统先给“候选 + 理由”，**用户拍板**——不替用户定；
3. 与“一次一问”铁律一致：一次只抛一个问题；
4. 用户答“继续/你定”才算授权自动推进，否则保持追问；
5. **每问必附推荐**——每个问题都附系统推荐答案或倾向，用户只需“反应/确认”，不必从白纸开始；
6. **能自查就不问**——能从资料/证据基底查到的信息，系统自查补齐，不占用用户提问额度，把注意力只留给真正的决策点。

## 四之二、七道确认点题干（半卡兹克化 · v2.2）

> 改造标准：每道题干自带四要素——**背景一句 / 为何此时问 / 问句本体 / 答案权重与不答后果**。外层对话协议不变，只把题干精度提到卡兹克级；七道题干同步以卡入 thinking-protocols 登记册。

**S1 元层诊断**
背景：守门①刚放行，O2 十变量已锁，思维框架未选。为何此时问：模式与视角决定六环“看什么”，进环前不定则全链受染。
问：“四要素复核结论已呈上——哪一条您认为没锁死？模式默认〔推荐卡〕，换卡请点名。”
权重：定六环透镜与视角检索词｜不答：按推荐配置推进，元层只此一轮不再补问。

**S2 锚定**
背景：O 层给了研究问题，“本稿立得住的那句话”尚不存在。为何此时问：判断句是承重墙，先立靶才有可守可攻。
问：“用一句话说，这篇最关键的矛盾是什么？答完我给判断句候选。”
权重：定主矛盾表述｜不答：若用户说“你定”，按证据基底自拟并标〔假设〕待 S3 回炉。

**S3 试杀**
背景：判断句候选在桌上但未挨过打。为何此时问：廉价试杀窗口只在结构设计之前——杀在 S3 成本一句改写，杀在 C5 成本整章重写。
问：“三点攻击已列（≥1 为替代解释/竞争框架）。第 X 点最致命——您如何回应？”
权重：回答直接改写判断句或触发回 S2｜不答：🔒 停轮挂起，P0 转草稿。

**S4 拆解**
背景：判断句幸存，现在修路。为何此时问：路径决定 C1 检索方向与章节骨架，错路进 C 层即沉没成本。
问：“证据、结构两条线草案在此——哪条要调整？”
权重：生成 C1 检索关键词与章节承诺｜不答：默认按草案放行。

**S5 锁基调**
背景：路修好，最后决定全稿说话姿势。为何此时问：基调须晚于结构、早于成文，位置不可前移。
问：“重论证逻辑还是重信息密度？（推荐 X，因为……）”
权重：二选一即锁入 P0 卡论证基调行｜不答：🔒 停轮挂起。

**S6 成型**
背景：五项裁决齐，组装施工图。为何此时问：组装取舍（字段详略、预案写法）需用户过目。
问：“卡上三处取舍标了 A/B——逐点确认。”
权重：定稿 P0 卡内容｜不答：默认推荐项落卡。

**S7 验证**
背景：图成型，出门前照镜子。为何此时问：失败信号只有用户知道。
问：“最可能让论证失效的假设是什么？”
权重：填入可证伪行供 C5 复查对照｜不答：助手代拟并标〔假设〕，自动交付守门②。

## 七、挂载边界（不做什么）

1. **不替代 C 层环节认知演进挂载**——C9 联合评审 🔴 可再借认知演进挂载双向钢人，属 C 层环节级加深，与 S 正交
2. **不替 C6 定文风**——④表达在 S 只锁论证基调（二选一），话术底线归档位指令包
3. **不跑重量级验证**——⑥验证在 S 用轻量 3 项，重量级（反事实重推+批驳书）留 C9
4. **不触发模式角色扮演**——模式库经认知演进挂载适配层只借心智模型（呼应认知演进挂载边界声明）
5. **不因 S 增重流程**——S 仍是任务级一次，但**这一次完整走六环+七确认点**；交互节奏由追问化纪律控制，不摊到 C 层

## 九、灵魂复活机制（v10.4 补回 · 复用 thinking-protocols 现有引擎）

> 本节恢复被 v10 默认关掉的“认知演进器灵魂”。所有机制均直接复用 thinking-protocols 已有文件，不重造。

### 9.1 不确定宣言（精神锚点）
S 层入口（守门①放行后、S1 之前）呈现浓缩版（≤3 行）：
> 星躔 S 不承诺“最佳答案”，只承诺“想得更清楚”。每一次追问、每一个确认点，都是把您无意识的选择翻译成可见的思维偏好；最终拍板永远属于您。

### 9.2 模式库（原版思维模式 · first-class）
S1 元层**默认呈现**模式选择（不默认关）：
- **选**：从 8 张模式卡加载心智模型驱动六环——① 李继刚·追本之箭（求本质/求根因，纵向深潜）② 毛泽东·矛盾分析（求策略/权衡，系统辩证）③ 求是·实事求是（信息不足/决策前，调查先行）④ 费曼·以教促学（检验理解/反自欺）⑤ 芒格·多元格栅（决策审视/逆向思考）⑥ 纳瓦尔·杠杆与第一性（重新定义/加杠杆）⑦ 见路不走·循规律（路径依赖/从众焦虑，预留）⑧ 塔勒布·反脆弱（风险/不确定性，预留）。卡详情见 thinking-protocols `references/modes/index.md`。
- **不选**：走通用六环基线（①流式追问②双向钢人③四象限④三选一⑤双粒度⑥轻量验证）。
- **混合**：元层指定顺序（如“先毛定矛盾，再李挖本质”）。
- **红线**：模式 skill 经适配层只借心智模型，不进入角色扮演；学术/公文交付不启用人物表达 DNA（除非显式要求）。

### 9.3 视角银行（perspective-bank）
- S1 检索 thinking-protocols `data/perspectives/bank.md`，匹配本稿相关视角 → 呈现 3-5 个深挖方向（矩阵 + 相关度×影响度评分，复用 `references/perspective-bank.md`）。
- 新视角经用户确认后**入库**（`data/perspectives/bank.md`），跨稿累积。

### 9.4 教练记忆持久化（画像·轨迹·视角）
每个确认点回显“选择即偏好”后，**双写**：
1. 本稿偏好清单（C5 → P5 就绪包，易失，随稿）；
2. thinking-protocols 持久档案（跨稿累积）：
   - `data/profiles/profile.md`：偏好画像，每条回显即一条证据；
   - `data/traces/YYYY-MM-DD.md`：思维轨迹，记录本次所用模式 + 关键取舍；
   - `data/perspectives/bank.md`：新视角入库（见 9.3）。
> 效果：星躔“越写越懂用户”，而非每稿从零问起。

### 9.5 与档位的正交边界
- **档位** = 写什么文体 / 表达规范（O2 定）；**模式** = 用什么思维框架想（S1 定）。二者正交，互不吞并。
- v10 错误假设“档位吸收模式选择”已被纠正：模式选择回归 S1 元层 first-class，档位不再“承接”它。

### 9.6 双产出机制（v10.4.1 补丁 · S7 后必交两份，缺一不算收尾）
> 原版认知演进挂载终点交付 = 【方案正文 + 推理依据 + 验证报告 + 执行建议】。v10.4 首跑只交了“方案正文”（P0 卡），把报告和执行建议丢了。本机制根修：

**产出 A —— P0 论证锚定卡（施工图）**：给 C 层 C1 的唯一输入口，模板见第五节。回答“论证往哪走”。

**产出 B —— P0-R 认知演进挂载结果稿（答卷 · R=Report）**：给用户的答卷，回答“这次想清楚了什么”。产物编号 **P0-R**（与 P0 同属 S 层、同生命周期），必须包含六节：

```markdown
# {稿件名} S 层认知演进挂载结果稿（{版本/日期}）

## 一、认知演进挂载总览          （对象/档位/深度/模式/视角/确认点通过数/产出清单）
## 二、七确认点全记录    （每环：问了什么 → 用户选了啥 → “选择即偏好”回显）
## 三、验证报告（S7）    （轻量 3 项正式版：自洽/韧性/可证伪 + 证据可得 + 风险预警≥2条）
## 四、认知演进挂载结论          （判断句 + 论证锚点 + 关键拍板 + 结构骨架 + 表达基调）
## 五、回显汇总          （偏好证据清单 + 落盘位置：profile/traces/perspectives）
## 六、执行建议          （下一步 C1 怎么干：账本方向/检索词/优先补料项/建档规则）
```

**纪律**：
1. S7 验证通过、守门②放行时，A、B **同时产出**，先交 B（用户审阅）再放 A 进 C 层；
2. B 的“三、验证报告”是 S7 正式版（100-200 字摘要），P0 卡尾部只留三行勾引用，不重复写；
3. B 的“二、确认点全记录”是回显的汇总——回显纪律（第三节第 5 条）要求每步即时回显，B 负责把它们收拢成一张答卷；
4. 挂起态解除时，B 同步标记“原挂起项已裁决”，供用户核对；
5. **挂起态下 B 同步交付草稿版**（标记挂起项 + 待裁决项，不标“已通过”）——B 与 A 同生命周期：A=草稿则 B=草稿，A 定稿则 B 定稿，不存在“A 已定稿而 B 未交”。

## 十、成稿复合评审出口（P0-CR · v12.6 新增）

> **适用**：stage④定稿（或论证已完整的续写稿）＋校验类诉求（评审/润色/投稿定位）。**新稿不走本节**，保持 9.6 双产出。
> **一句话**：成稿的 S 层出口 = **一份 P0-CR 复合评审报告**——S1 复核＋S7 补充 2 项＋C9 学术评审＋返修裁决表。一条链，两种出口（新稿=守门②双产出，成稿=复合评审单产出），不增环节、不重复评审。

**出口规则**：
1. **S1 复核必跑**（四要素＋六维挂靠，确认论证锚定没跑偏）；
2. **批量跳过 S2-S6**（用户显式确认，声明“跳过 S2-S6：理由=已有论证资产”）；
3. **S7 瘦身为 2 项**——证据可得＋风险预警≥2（自洽/韧性/可证伪由 C9 学术评审覆盖，不重复）；
4. **C9 学术评审提前接入**（五评审制＋六维评分，评审引擎同 C 层资产）——成稿核心风险不在“没想清楚”，在“过不过得了评审”；
5. **C 层 C9（守门⑪）复用报告结论，不重复评审**，守门⑪ 以报告为准。

**P0-CR 模板（六节＋裁决表）**：

```markdown
# {稿件名} S 层复合评审报告（P0-CR-{序号} · {版本/日期}）
## 一、总览        （档位/流程深度/阶段/评审阵容/复用资产清单）
## 二、S1 复核结论  （四要素逐条 + 六维挂靠确认）
## 三、S7 补充验证  （证据可得 + 风险预警≥2）
## 四、C9 学术评审  （五席结论 + 六维评分 + 评审引擎记录）
## 五、问题清单    （硬伤级 / 优化级 两级，逐条编号）
## 六、返修裁决表  （问题号 × 对应返修工序 × 用户裁决：硬伤→回 C2-C5 对应工序 / 优化→C10 / 无→C7-C11 校验线）
```

**纪律**：
1. 裁决完成后按裁决进 C 层：硬伤→先回对应工序补料重写再走校验；优化→C10 返修；无→C7-C11 线；
2. P0-CR 同生命周期：裁决完成即定稿，随 C11 并入就绪包并**按 P0 卡归档字段（领域×范式×判断句类型）入论证资产库**；
3. 论证资产库为轻量档案（跨稿复用检索键=归档字段）：新稿 S 开工先查库，命中同域模板 → 用户确认“复用/重跑”；成稿“批量跳过 S2-S6”＝复用已归档论证资产——**跳过不白跳，省下的论证沉淀为资产**；
4. **裁决表级别可复核（C-11 · 实测补）**：裁决表为**起点非终审**——C 层执行先对稿核对裁决项（硬伤/优化），级别修正须满足：对稿证据可引＋**用户确认**＋记入决策流水；**模型禁单方撤销硬伤**（禁静默降级）。
