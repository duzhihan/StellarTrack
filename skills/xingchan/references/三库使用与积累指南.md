# 三库使用与积累指南（K/M/T · v12.6.1）

> 定位：K 知识库／M 方法库／T 工具库的**使用方案＋积累方案＋内置/接入双轨＋配置说明**。本指南建在系统使用说明体系之上——使用指南.md（系统操作手册）尾章指向本文件；安装配置同步见 00B 安装与 Skill 配置指南。
> 三库一句话：**M 管每步怎么干，K 管材料从哪来，T 管用什么家伙。**（准入与修改细则见 MKT库管理规范.md，本指南不重复。）
> **接入优先（v12.6.1）**：若你已有自己的知识库/方法库/工具箱目录，应**接入已有目录**而不是为星躔新建文件夹——定位方式见本章“〇、三库定位与接入”；接入后检索范围＝内置＋接入根，用户库只读、不被改造。

## 〇、三库定位与接入（接入优先于新建）

三库默认随包零配置（内置位见 §一）；**启动时先读 `xingchan/config.json`**，未配置则全部走内置默认。config.json 结构（install.py `--configure-libs` 或 `--libs` 生成，可手动编辑）：

```json
{
  "version": 1,
  "kbase":   {"builtin": "data/kbase",   "extra_roots": ["D:/我的知识库"]},
  "methods": {"builtin": "references/methods", "extra_roots": ["E:/方法卡"]},
  "toolbox": {"builtin_registry": "references/C环节skill注册表.md",
              "extra_registries": [], "skills_dirs": ["<技能根>"]}
}
```

| 键 | 含义 | 接入约定 |
|---|---|---|
| `kbase.extra_roots` | 接入的已有知识库根（可多个） | 只读检索（O2 同题查重/C2 线索/S1 证据基底范围＝内置＋接入根）；写入默认落内置 `data/kbase/`，防污染用户库；若要写入进自己的 Obsidian，手动把写入位指过去（见第四节） |
| `methods.extra_roots` | 接入的已有方法卡/模板目录 | 按卡执行须符合六字段制；未达准入的条目只作线索不按卡执行 |
| `toolbox.extra_registries` | 接入的工具登记文件（对齐注册表格式） | 已装 skill 仍须过 `check-engines.py` 体检 |

**读取时点**：O2 步骤①（同题查重）与 S1（证据基底）检索前读一次 config.json 确定 K 库范围；各工序开工首步（方法卡/引擎声明）读一次确定 M/T 范围。会话内如有改动（E 层沉淀后），下次读取即生效。

## 一、三库是什么、长什么样

| 库 | 管什么 | 随包载体 | 准入 |
|---|---|---|---|
| **K 知识库** | 材料与经验从哪来（规则/线索/失败档/禁区/校准） | 内置基础库 `data/kbase/`＋词法区/规则区/反馈区等随包文件；外接增强（可选） | K 库写入侧四闸（来源可回指/线索格式/不预存结论/用户点名回流） |
| **M 方法库** | 每步怎么干（六字段方法卡＝执行标准） | `references/methods/`（方法卡 01-06＋母版适配卡） | 四闸：复用（≥2 稿）/范式/格式（六字段）/裁决 |
| **T 工具箱** | 用什么家伙（工序×档位引擎总表） | `references/C环节skill注册表.md`＋`T工具箱_待加载清单.md` | 转正四步：登记（溯源五件套）→审计→归属→裁决 |

### T 库 · 引擎强制触发（C-10）

每道工序开工首步＝读注册表该工序默认引擎 → 声明“本工序调用 X 引擎”；未调用须显式声明理由（未安装/不可达/人工替代）→ 走降级条款（C-8）＋记 `data/engine-gaps.md`；未声明即开工 → 守门不放行。待加载清单→转正四步→注册表，是 T 库的晋升路径。

## 三、积累方案（怎么积累）

### 节奏表

| 周期 | 动作 | 依据 |
|---|---|---|
| **每稿** | E1 分发→第二跳入库：九管道×三库口（规则→rule-base/摩擦→frictions/灵感→insight-inbox/失败→failure-archive/禁区→no-go-list/引擎缺口→engine-gaps/校准→calibration-ledger） | E1 分发裁决（SKILL.md §六） |
| **每月** | insight-inbox 月检回流：同类命中 ≥2 次升 K 线索或 rule-base 候选；未命中删除留痕 | E1 管道（废料回收机制） |
| **每季** | E2 复盘三查：M 卡使用率／K 库死链／T 工具许可变更；校准台账“上次改进落地没”＋引擎调度落地 | MKT库管理规范 §五＋E2 |

### 积累通道（写作产物回流纪律）

| 通道 | 职责 | 回流规则 |
|---|---|---|
| **E1 分发**（主通道） | 每稿经验入库 | 直接走九管道×三库口 |
| **知识库读写通道**（阅读积累） | 外部阅读→知识条目录入 | 写作产物回流经此通道，**不自动回写**（用户点名方入） |
| **札记供给通道** | 札记=知识条目素材 | 经知识库读写通道录入，本身不做检索 |
| **灵感捕获通道** | 梦境/灵感记录→灵感暂存箱 | 灵感直供 O 层触发器，素材经用户确认后方可入 K |

## 四、K 库双轨：内置基础库 ＋ 外接增强库

### 4.1 内置基础库（默认·随包·零依赖）

- 载体：`data/kbase/` 文件式四层（RAW→Source→Wiki→MOC）＋分区映射（见该目录 README）
- **不依赖任何外接资源即可全功能运行**——写作、沉淀、检索全部走随包文件
- 适合：单机使用、隐私敏感、无第三方依赖的场景

### 4.2 外接增强库（可选·升级路径）

| 外接资源 | 优点 | 适用 |
|---|---|---|
| **Obsidian**（本地知识库） | 双链可视化（关系图谱）／全文检索／移动端同步／插件生态 | 知识体量大、需要图谱漫游与移动积累 |
| **知识库服务**（语义查询类） | 自然语言查询／API 集成／跨库聚合 | 需要语义检索、接入自动化流程 |
| **移动采集端**（剪藏类） | 随手采集入 K（只收不炼） | 碎片化阅读积累，定期导出灌入 |

**安装配置**：
1. Obsidian：安装官方客户端 → 打开仓库指向 `data/kbase/`（或将其 Wiki 层映射为仓库）→ 双链/图谱即用；四层目录保持原结构
2. 知识库服务：按服务商文档部署/配置 → 连接基础库 Wiki 层 → 检索接入星躔知识库读写通道
3. 移动采集端：安装 App → 配置导出目标 → 定期导出至 `data/kbase/RAW/`，由知识库读写通道整理

**同步/迁移**：启用外接后，基础库条目可批量导入外接库；**双向以 `data/kbase/` 为源**（基础库不失效，外接是视图增强）。写作产物回流仍经知识库读写通道，不自动回写。

## 五、常见问题

- **不装 Obsidian 能用吗？** 能。基础库随包零依赖，全部积累/检索走文件。
- **外接库和基础库冲突吗？** 不冲突。外接是增强视图，源在基础库。
- **新经验入库要几步？** 两步：E1 分发定接收器（第一跳）→ 过准入落三库口（第二跳）。
- **M 卡什么时候能建？** 同一打法跨 ≥2 稿复用或经实战纠偏 ≥1 次（复用闸），六字段齐备，用户拍板。
